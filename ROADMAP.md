# ROADMAP vraw

План развития проявщика (согласовано с Игорем). Устройство того, что уже
сделано, — в PROJECT.md. Пункты внутри разделов — по приоритету.

## В планах

### Высокий приоритет

- [ ] **Баланс белого**: ползунки температуры (K) и оттенка (tint) через
      `params.user_mul`, переключатель «камерный/авто», пипетка серого (клик
      по нейтрали задаёт множители каналов), пресеты (дневной/тень/лампа).
      Через LibRaw `user_mul` требует перепроявки (паттерн «Пересветов»);
      альтернатива — множители RGB в пайплайне (живые ползунки, но без
      учёта клипа до демозаики).
- [ ] **Резкость (sharpening)**: unsharp mask / деконволюция как финальный
      шаг проявки. Инфраструктура sqrt-домена и вейвлета à trous уже есть
      (`pipeline/denoise.v`) — логичное место.
- [ ] **Кадрирование и геометрия**: crop с пропорциями, поворот/выравнивание
      горизонта (произвольный угол + автокроп), отражение. Базовая
      компоновка перед сохранением.

### Средний приоритет

- [ ] **Нейросетевой шумодав (AI denoise)** — идея 27.09.2026. Открытая
      модель под реальный шум камеры: NAFNet (Apache 2.0, SIDD) — основной
      кандидат, SCUNet — запасной; DnCNN/FFDNet маленькие, но обучены на
      синтетическом шуме и на реальных кадрах слабее. RAW-модели до
      демозаики (PMRID) лучше в теории, но требуют переделки связки с LibRaw.
      Встраивание: ONNX Runtime через C API (`#flag -lonnxruntime`), модель
      `.onnx` рядом с программой; место — подготовка сырья в фоновом потоке
      (как `pipeline.denoise`), плитки с перекрытием, ползунок «сила» —
      смешение с исходником. Модели обучены на sRGB — буфер переводить в
      гамма-пространство и обратно. Главный риск — скорость на CPU ноутбука
      (ожидаемо секунды на превью и десятки секунд — минуты на 24 Мп), поэтому
      режим «включить», а не живой ползунок. **Первый шаг** — прототип на
      Python + onnxruntime на кадре высокого ISO (IMG_0631, ISO 5000):
      сравнить с вейвлетным шумодавом по качеству и времени, и только при
      заметном выигрыше встраивать в V.
- [ ] **EXIF в итоговый JPEG**: дата, ISO, объектив, копирайт; проще всего
      скопировать exiftool'ом после `stbi_write_jpg`.
- [ ] **Clarity / локальный контраст**: unsharp по маске люмы; `blur_luma`
      из «Тени/Света» уже даёт размытую люму.
- [ ] **Управление цветом**: выбор рабочего/выходного пространства
      (sRGB / Adobe RGB / ProPhoto), встроенный ICC-профиль в JPEG. Сейчас
      пайплайн жёстко в sRGB-праймерис, JPEG без профиля.
- [ ] **Workflow**: пакетная обработка (папка RAW → папка JPEG),
      пресеты/сайдкары настроек (.xmp рядом с RAW), undo/redo, навигация
      след./пред. по файлам в GUI.
- [ ] **Форматы вывода**: TIFF/PNG 16 бит для дальнейшей обработки (сейчас
      только 8-битный JPEG).

### Низкий приоритет

- [ ] **`vign_strength` — одна константа на все объективы** (замечание
      ревьюера): 0.3 подобрано под ВЫРОЖДЕННЫЙ профиль RF 24-50, где карта
      усиления выворачивается. Для нормальных профилей (виньетка честная,
      без ореола) это смягчение недокорректирует — углы останутся темнее,
      чем следует. Правильнее смягчать только вырожденную зону (где
      усиление близко к `gain_cap`) или сделать силу параметром
      профиля / эвристикой по крутизне карты.
