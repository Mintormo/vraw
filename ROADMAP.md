# ROADMAP vraw

План развития проявщика (согласовано с Игорем). Устройство того, что уже
сделано, — в PROJECT.md. Пункты внутри разделов — по приоритету.

## В планах

**Связи между пунктами.** Неразрушающее редактирование (снимок состояния
+ сайдкары) — фундамент для браузера папки и пакетной обработки: без него
при переключении кадров правки терялись бы, а пакету неоткуда брать
настройки. Порядок: снимок состояния, история, сайдкары и браузер папки (сделано)
→ пакетная обработка. Форматы экспорта независимы, но их диалог экспорта
потом переиспользует пакетная обработка.

### Высокий приоритет

- [ ] **Баланс белого** (параметры уточнены 27.09.2026). Секция «Баланс
      белого» в панели, настройки - в EditState (история, сайдкар).
  - **Режим**: «Как снято» (камерный ББ, сейчас по умолчанию), «Авто»
    (серый мир / по светлым нейтралям), «Свой».
  - **Температура**, K (~2000-12000, шкала нелинейная - в майредах) и
    **оттенок (tint)**, зелёный <-> пурпурный (-150..+150); от них -
    множители каналов R/G/B.
  - **Пипетка серого**: щелчок по нейтрали на превью задаёт множители
    (усреднение пятна 5x5 или 9x9), затем показывает получившиеся K и tint.
  - **Пресеты**: дневной свет, облачно, тень, лампа накаливания,
    люминесцентная, вспышка.
  - **Как применять**: через LibRaw `params.user_mul` - точнее (до
    демозаики и с учётом клипа), но нужна перепроявка (паттерн
    «Пересветов»: применять по отпусканию); альтернатива - множители RGB
    в пайплайне (живые ползунки, но без учёта клипа). Скорее всего:
    ползунки - в пайплайне вживую, а при экспорте - через user_mul.
- [ ] **Резкость (sharpening)** (параметры уточнены 27.09.2026). Финальный
      шаг проявки, секция «Резкость» в панели, настройки - в EditState.
  - **Величина** (amount, 0..150%) - сила подъёма контраста деталей.
  - **Радиус** (0.5..3 px) - размер деталей, которые подчёркиваются.
  - **Детализация / порог** (threshold, 0..100) - не усиливать слабые
    перепады, чтобы не поднимать шум.
  - **Маска по краям** (masking, 0..100) - резкость только на контурах,
    ровные области (небо, кожа) не трогаются; просмотр маски с Alt.
  - **Только по яркости** - резкость по люме, без цветных ореолов.
  - **Метод**: unsharp mask (быстро) или деконволюция
    Ричардсона-Люси (RawTherapee «Capture sharpening») - позже.
    Инфраструктура sqrt-домена и вейвлета à trous уже есть
    (`pipeline/denoise.v`) - логичное место. На превью half-size резкость
    выглядит иначе, чем на полном кадре: радиус масштабировать, для
    оценки - просмотр 1:1.
  - **Резкость на выход** (под размер экспорта) - в диалоге экспорта,
    см. «Форматы экспорта».
- [ ] **Кадрирование и геометрия**: crop с пропорциями, поворот/выравнивание
      горизонта (произвольный угол + автокроп), отражение. Базовая
      компоновка перед сохранением.

### Средний приоритет

- [ ] **Сравнение снимков** — идея 27.09.2026. Два режима в меню «Вид».
  - **Два кадра рядом**: в области просмотра два снимка бок о бок (или
    один над другим для вертикальных) — например, выбрать лучший из
    серии. Второй кадр — выделенный в ленте (одиночный щелчок уже только
    выделяет, не открывает). Синхронный зум и панорама (одинаковый
    участок в обоих), переключение «какой редактируется» щелчком по
    половине; подписи имён и отметка активного. Второму кадру нужна своя
    загрузка превью с его правками из сайдкара (фоновый загрузчик уже
    есть — вторая копия `LoadJob`/буферов).
  - **До и после**: тот же кадр без правок и с правками. Варианты:
    бок о бок, разделитель-шторка (перетаскиваемая вертикальная линия:
    слева «до», справа «после»), переключение по удержанию клавиши
    (например, `\`). «До» — нейтральные настройки (как «Открыт файл»)
    или выбранная запись истории; «после» — текущее состояние. Дёшево:
    сырьё то же, нужен второй прогон `pipeline.apply` с другими Params
    во второй буфер холста.
  - Из vgui: два Canvas со связанными зумом/панорамой (события
    `set_zoom`/скролл одного переносить на другой) или один Canvas со
    своей отрисовкой шторки.

- [ ] **AI-шумодав: развитие** (сделан 28.09.2026, см. «Сделано»)
  - **Фоновый досчёт полного кадра**: после прогона превью сразу считать
    полный кадр в фоне (~2.5 мин) и держать результат (~150 МБ) — экспорт
    тогда без ожидания. Сброс при смене пересветов/объектива.
  - **int8-версия модели** (32 МБ вместо 117, на ~14% быстрее, на
    IMG_0634 визуально так же) — проверить на нескольких кадрах.
  - **SCUNet** — качество чуть выше на ровных тёмных участках, но в 5 раз
    медленнее (~13 мин на кадр); int8 его не ускоряет. Как опция «лучше,
    но долго».
  - Пакетная обработка с AI — прогресс по кадрам, ~2.5 мин на кадр.
- [ ] **EXIF в итоговый JPEG**: дата, ISO, объектив, копирайт; проще всего
      скопировать exiftool'ом после `stbi_write_jpg`.
- [ ] **Clarity / локальный контраст**: unsharp по маске люмы; `blur_luma`
      из «Тени/Света» уже даёт размытую люму.
- [ ] **Управление цветом**: выбор рабочего/выходного пространства
      (sRGB / Adobe RGB / ProPhoto), встроенный ICC-профиль в JPEG. Сейчас
      пайплайн жёстко в sRGB-праймерис, JPEG без профиля.
- [ ] **Браузер папки: развитие** (лента сделана 27.09.2026)
  - **Предзагрузка соседнего кадра**: загрузка уже фоновая (окно не
    замирает, превью камеры сразу), но проявленный кадр приходит через
    ~0.5–1.5 с — можно заранее грузить следующий кадр в фоне.
  - **Отметка «экспортирован»**: путь последнего экспорта — в сайдкар
    (save_worker знает src), кружок другого цвета на миниатюре.
  - **Рейтинг и флажки** для отбора (клавиши 0–5, P/X), фильтр ленты.
  - Ширина панели сейчас доля окна (Splitter держит ratio) — при
    растягивании окна панель тоже растёт; можно держать пиксели.
- [ ] **Пакетная обработка RAW** — идея 27.09.2026. Проявка многих кадров
      за раз без ручного открытия каждого.
  - **Что обрабатывать**: выбранные в браузере кадры, вся папка или
    список файлов.
  - **Какие настройки**: у каждого кадра — свои из сайдкара; либо
    одинаковые для всех — текущие настройки, сохранённый пресет или
    «скопировать настройки с этого кадра на выбранные» (с выбором групп:
    тон, цвет, шумодав, коррекция объектива).
  - **Куда и как**: папка назначения, шаблон имени (`{имя}`, `{дата}`,
    `{номер}`), формат и параметры экспорта (см. «Форматы экспорта»),
    пропуск или перезапись существующих файлов.
  - **Выполнение**: в фоне, воркеры с собственными LibRaw/lensfun (как
    нынешний `save_worker`). Параллельно 2–3 кадра — упор в память (полный
    кадр 24 Мп в u16 ~145 МБ плюс копии на шумодав и коррекцию). Прогресс
    («12 из 40»), отмена, журнал ошибок; окно при этом остаётся рабочим.
  - **Только в окне** (решено 27.09.2026, консольной версии нет).
    Камерная кривая в сайдкаре не хранится — пакет считает её для
    каждого кадра, как загрузчик (`camera_curve` в `loader.v`): по
    превью ПОЛОВИННОГО размера (пересветы и объектив из настроек, без
    шумодава), а не по полному кадру — там кривая заметно другая
    (IMG_0817: до 11 из 255 в средних тонах). Дальше — `develop_full`.
  - Зависит от «Неразрушающего редактирования»; удобнее всего вместе с
    браузером папки.
- [ ] **Форматы экспорта** — расширено 27.09.2026. Сейчас только 8-битный
      JPEG (`stbi_write_jpg`). Пайплайн внутри в f32 — для 16-битного
      вывода нужен вариант `apply()` с выходом u16 (без квантования в 8 бит
      и без дизера). Кандидаты:
  - **TIFF 8/16 бит** (libtiff, в apt) — для дальнейшей обработки в
    других программах; без сжатия / LZW / Deflate.
  - **PNG 8/16 бит** — 8 бит умеет stbi; 16 бит — через libpng (в apt).
  - **WebP** (libwebp) — компактно для веба, с потерями и без.
  - **AVIF** (libavif) и **JPEG XL** (libjxl) — современные форматы,
    10–12 бит, заметно меньше JPEG при том же качестве; проверить наличие
    библиотек нужных версий в apt.
  - Общее для всех: встроенный ICC-профиль (см. «Управление цветом») и
    EXIF (см. «EXIF в итоговый JPEG»), где формат это позволяет.
  - **Диалог экспорта** вместо одной кнопки: формат, разрядность,
    качество/сжатие, изменение размера (по длинной стороне, в пикселях
    или процентах), резкость на выход, имя файла и папка. Последние
    настройки запоминаются; эти же настройки использует пакетная
    обработка.

### Низкий приоритет

- [ ] **`vign_strength` — одна константа на все объективы** (замечание
      ревьюера): 0.3 подобрано под ВЫРОЖДЕННЫЙ профиль RF 24-50, где карта
      усиления выворачивается. Для нормальных профилей (виньетка честная,
      без ореола) это смягчение недокорректирует — углы останутся темнее,
      чем следует. Правильнее смягчать только вырожденную зону (где
      усиление близко к `gain_cap`) или сделать силу параметром
      профиля / эвристикой по крутизне карты.
