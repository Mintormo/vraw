# GUI: кадрирование и поворот

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Кадрирование и поворот** (`crop.v`, секция «Кадрирование и
  поворот» после «Коррекции», свёрнута). Настройки — в EditState
  (история, сайдкар, группа `crop`): `geom` и ограничения рамки —
  `crop_aspect` (ключи `crop_aspects`: '' свободно, `shot` — как снято,
  1:1 … 65:24, `custom` — `crop_aw:crop_ah`), `crop_portrait`
  (вертикальная — стороны меняются). Размер на выход — не здесь, а в
  окне «Экспорт» (`export_setup.v`).
  - **Превью**: `ensure_geom` в начале `apply_pipeline` — `glin`/`gmask`
    (`gw×gh`) из `linear`/`mask` через `geom_apply`, пересчёт только при
    смене ключа `GeomKey` (номер сырья `lin_gen` — растёт при каждом
    новом `linear`; геометрия; режим); холст — под размер (смена размера
    вписывает заново), карта дымки — по `glin`. Холст сам больше нигде не
    меняет размер (раньше — `on_load_done`, `load_preview`). Вне режима
    превью — обрезанный кадр, гистограмма по нему; пипетка ББ, «Авто» ББ
    и автотон берут `glin` (то, что на холсте).
  - **Режим кадрирования** (`set_crop_mode`: кнопка «Кадрировать» /
    «Готово (Enter)», «Правка - Кадрирование» R): превью — весь R
    (`crop = false`), рамка — `cv.on_overlay` (vgui, экранные координаты,
    без пересчёта снимка): затемнение вне рамки, рамка, 8 ручек, сетка
    (`settings.crop_grid`: трети, диагонали из углов под 45°, золотое
    сечение, нет; мелкая сетка — пока тянут угол или ведут горизонт),
    размер на выход у нижнего края; гистограмма — только по рамке
    (`box_pixels`). Мышь (`crop_input` из `cv.on_input`, координаты —
    `ev.fx/fy` без клампа, попадание в ручку — в экранных пикселях,
    радиус 10): ручка угла — опора в противоположном углу, стороны —
    противоположная сторона (с пропорцией — вторая сторона по центру);
    внутри — перенос (сначала по x, потом по y: скользит вдоль края);
    снаружи — **поворот кадра** (как в Lightroom): угол мыши вокруг
    центра рамки, отсчёт от геометрии нажатия (`CropDrag.geom`, `a0`;
    мышь по часовой — кадр по часовой, угол минус, шаг 0.1°), рамка —
    `refit` от геометрии нажатия (сжатая на большом угле вернётся при
    обратном повороте); мелкая сетка и угол у верхнего края рамки, запись
    «Поворот: угол»; **Ctrl+перетаскивание снаружи** — новая рамка от
    точки (направление — по первому движению); двойной щелчок —
    наибольшая рамка по центру; курсор — стрелки изменения размера /
    перенос / рука снаружи (своего курсора поворота в SDL нет) / крест с
    Ctrl (`vgui.set_cursor`). Отпускание — запись «Кадрирование: рамка».
    Пересчёт превью по ходу поворота (и живых ползунков) — `defer_fx`:
    один на пачку событий через `app.post` (выполняется после всех
    накопившихся событий); прямой пересчёт (~0.25 с с поворотом) на каждое
    движение копил очередь — 100 движений догонялись 26 с, теперь 0.26 с. Вход в кадр без рамки и без пропорции —
    пропорция последнего выбора (`settings.crop_aspect`; у вертикального
    кадра — вертикальная), рамка наибольшая. Enter — выйти, Esc —
    `crop_cancel`: настройки кадрирования на момент входа
    (`crop_before`), запись «Кадрирование: отмена». Смена/закрытие кадра —
    `crop_leave`.
  - **Угол** — живой ползунок (`SliderCfg.live`: пересчёт и при драге —
    через `defer_fx`, запись — по отпусканию) и поле ручного ввода справа
    в ряду «Повернуть» (`CropUi.angle_in`, TextInput): Enter →
    `set_angle_text` — `parse_angle` («-2.5», «−2,5», «+3», «3°»; «ю»/«б» —
    тоже разделитель: точка и запятая в русской раскладке), округление до
    0.1, ±45, запись «Угол: …»; не число — предупреждение тостом. Поле в
    фокусе `sync_crop_ui` не перезаписывает (набор не сбивается), после
    Enter текст приводится к «-3.5». Оба пути — `geom_with_angle` → `refit`: рамка, бывшая
    наибольшей по центру, остаётся наибольшей (растёт и сжимается с
    углом), иначе сжимается к своему центру до кадра. **Горизонт**
    (кнопка-линейка, включает режим): провести по горизонту или вертикали
    → `horizon_angle`, запись «Выпрямление». **Поворот на 90°** и
    **отражения** — рамка поворачивается/отражается вместе с кадром,
    пропорция поворота меняет ориентацию,
    отражение меняет знак угла.
  - **Перспектива** (07.10.2026): живые ползунки «Вертикаль» и
    «Горизонталь» под «Углом» (`CropUi.pv_sl` / `ph_sl`, `sync_crop_ui`
    выставляет их по геометрии). Рамку не трогают: кадр с перспективой
    заполнен целиком. Кнопка «Перспектива по двум линиям» (значок
    `columns-2` рядом с линейкой горизонта, включает режим
    кадрирования): провести две линии (`CropDragKind.persp`; первая —
    `st.persp_l1` на экране и `persp_v1` в пикселях V, жёлтым), после
    второй — `persp_line_done` → `pipeline.persp_lines` (R → V' →
    `persp_to_v`), угол — `geom_with_angle` (рамка как при повороте),
    запись «Перспектива по линиям: pv, ph, угол». Короче 10 px — не
    линия. Проверка на IMG_0991 (колонны, «Вертикаль» +40, линии по
    колоннам, найденным по яркости с точностью ±3 px): 40 → 18 — ровно
    то, что модель даёт для этих линий; глазом линии точнее.
  - **Пропорция** — список + кнопка ориентации (у свободной — рамка
    поворачивается вокруг центра); смена → `fit_ratio`: `best_box`.
    Ряды «Пропорция», «Своя» и «Сетка» активны только в режиме
    кадрирования (18.10.2026, `CropUi.a_row`/`c_row`/`g_row`,
    `sync_crop_ui`): вне режима рамки не видно, и смена пропорции молча
    меняла кадр. Угол, перспектива, автоперспектива и повороты — всегда.
    Своя — два поля (Spinbox 1..100). «Кадр: 5612 × 3157 px» —
    `crop_size` по полному размеру кадра
    (`raw.Developer.full_size`); у числовой пропорции высота выхода —
    по ширине (`out_geom`, `Geom.aspect`): 1:1 — ровно квадрат.
    У рамки на весь кадр `Geom.out_size` пропорцию не применяет — выход
    равен кадру (18.10.2026): пропорция бывает без своей рамки (у нового
    кадра — из настроек `crop_aspect`), и 4:5 на кадре 3:2 давала выход
    6000×7500, а `is_noop` (рамка на весь кадр) выбирал копию — фрагмент
    1:1 внизу кадра читал за сырьём (`geom_apply_region`, падение воркера).
  - **Экспорт** (`develop_full`): после Capture-резкости и маски —
    `geom_apply(out_geom)` сырья и маски, карта дымки по результату,
    `apply_image`, затем `resize_rgb_sharp` до `export_dims(ExportOpts.size)`
    (резкость на выход `ExportSize.sharp` — только при уменьшении).
  - **Миниатюры ленты** — с кадрированием и поворотом (см. «Браузер
    папки», `make_thumb`).
