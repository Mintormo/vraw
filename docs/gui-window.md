# GUI: окно, меню, настройки, общие паттерны

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Заголовок окна** (08.10.2026): «IMG_0817.CR3 - vraw», без кадра —
  «vraw» (`update_title`: при открытии кадра, закрытии и создании окна;
  дефис, не длинное тире — CLAUDE.md).
- **State**: `dev` (LibRaw), три слоя сырья превью: `dev_linear []u16`
  (прямо из LibRaw), `raw_linear` (после коррекции объектива, ДО шумодава),
  `linear` + `pw, ph` (рабочее сырьё пайплайна); `mask []u16` (размытая
  люма для «Тени/Света», ~0.35 с на превью; save_worker считает свою для
  полного кадра). Слои, которые ничего не меняют, — ОДИН массив на
  несколько полей (05.10.2026, −80 МБ живой памяти превью 24 Мп):
  `prep_compute` копирует сырьё только под правку — без коррекции
  объектива `raw_linear` = `dev_linear`, без шумодава и Capture
  `linear` = `raw_linear`; `ensure_geom` при `Geom.is_noop` (без поворота
  и обрезки) — `glin` = `linear`, `gmask` = `mask`. Поэтому буферы State
  только читаются: править на месте нельзя (подготовка и 1:1 берут их
  без копии); новый слой — новый массив. `edit EditState` (все настройки правки кадра, см.
  «Неразрушающее редактирование и история»), `quality`, `suppress bool`.
  Фоновая подготовка: `file_gen`, `lens_dirty`, `prep_running`,
  `prep_threads`, `prep_done`.
- **Компоновка и оформление** (тёмная тема): корень — VBox: меню
  (`vgui.menu_bar`, 28 px) и под ним горизонтальный `vgui.Splitter`
  (`top`/`st.hsplit`, полоса 3 px цвета `divider_color`, мин. 400 |
  360 px): область просмотра (VBox `st.viewer`, фон `viewer_bg`
  22,22,24) | правая панель (фон `panel_bg` 37,37,38, отступ 10:
  гистограмма и аккордеон в ScrollBox), при старте 440 px
  из 1280. Панель держит ширину в пикселях — режим vgui `Splitter.keep`
  (с 17.10.2026; раньше — невидимый виджет `PanelFit` перед корнем):
  `layout_work` ставит `set_keep(сторона панели, panel_width)` и
  `apply_keep` (доля нужна `center_strip` сразу), сплиттер в своей
  раскладке пересчитывает долю под новую ширину окна — растёт только
  просмотр; узкое окно ужимает панель до `panel_min_w`, настройка не
  меняется. Перетащили полосу — `keep_size` уже новый, `panel_dragged`
  пишет его в `settings.panel_w` (0 — 440 по умолчанию). Область просмотра — область
  снимка `st.view_area` (VBox, отступ 16 — фото не упирается в края) и
  под ней лента кадров папки (см. «Браузер папки»). В `view_area` Stack:
  холст `cv` и заглушка, видим один. Цвета — константы в gui.v. Тема —
  `theme := vgui.dark_theme()` → `create_app` (окно без своей темы
  получает её в add_window).
- **Меню** (`bar`, пункты `vgui.menu_action/menu_checkbox/menu_submenu`;
  сочетания клавиш — поле `shortcut` (меню их показывает и само
  разбирает нажатия) — см. «Горячие клавиши»; ниже — сочетания по
  умолчанию):
  «Файл» — «Открыть файл...» Ctrl+O (кадр + вся его папка в ленте),
  «Открыть папку...» Ctrl+Shift+O (`native_select_folder_dialog`),
  «Показать в папке» Ctrl+R (см. «Браузер папки»),
  «Экспорт...» Ctrl+E (во время экспорта второй не запускает, а
  снова открывает диалог экспорта), «Выход» Ctrl+Q;
  «Правка» — «Отменить» Ctrl+Z, «Вернуть» Ctrl+Shift+Z (Ctrl+Y —
  отдельно, горячей клавишей окна), «Копировать настройки...»
  Ctrl+Shift+C, «Вставить настройки» Ctrl+Shift+V (неактивен, пока
  ничего не скопировано или некуда вставить), флажок «Удаление пятен» Q (режим инструмента,
  см. «Удаление пятен»), «Пипетка баланса белого» W (08.10.2026, как
  кнопка раздела), «Сбросить тон» Ctrl+Shift+R (кнопки
  на панели больше нет);
  «Вид» — «Вписать» Ctrl+0, 50%, «100% (1:1)» Ctrl+1, 200%, «100% /
  вписать» Z (и пробел — горячей клавишей окна), флажок «До/после:
  шторка» Y, флажок «До/после: бок о бок» Shift+Y, флажок «Пересветы и провалы» J, флажки «Полноэкранный режим» F, «Лента кадров» F6,
  «Лента сверху», «Панель инструментов» F8, «Панель слева» (см. «Раскладка окна»), подменю «Фон вокруг снимка» (чёрный / тёмно-серый /
  серый 118 / белый — флажки как переключатель, `set_viewer_bg`) и
  подменю «Тема» (см. «Темы»).
  Флажок меню vgui сам переключает `checked` перед `on_toggle`.
  «Отбор» — 0–5 звёзд, P/X/U флажки, флажок «Переходить к следующему
  кадру» (см. «Отбор»); «Пресеты» — список пресетов, «Сохранить
  пресет...», «Управление пресетами...» (см.
  «Копирование настроек и пресеты»). Порядок меню (18.10.2026): Файл,
  Правка, Вид, Отбор, Пресеты; «Пресеты» — последнее (`st.presets_menu`
  — его индекс для `rebuild_presets_menu`).
- **Доступность элементов** (`avail.v`, 13.10.2026): пункт меню или
  виджет панели активен, только когда им можно что-то сделать.
  - Пункты меню — со своим условием `Need` (`avail_add` в main):
    `.frame` — кадр открыт, в т.ч. пока грузится (`frame_open`:
    `raw_path` и `loading` или `dev`; загрузка не удалась — нет):
    копирование настроек, «Сбросить тон», масштаб, до/после, JPEG
    камеры, пересветы, «Сохранить пресет...»; `.pixels` — превью готово
    (`frame_ready`): кадрирование, пятна, пипетка ББ, автотон; `.target`
    — отбор (`mark_targets`); `.frames` — «Выделить все кадры»;
    `.export` — экспорт идёт или есть что проявить; `.undo`/`.redo` —
    по истории; `.paste` — буфер и `paste_targets`; `.preset` — пункты
    пресетов (`st.m_presets`, меню пересобирается); `.pair`/`.swap` —
    сравнение; `.mask` — «Маска фильтра» (у кадра есть фильтры).
    Всегда активны: открытие, выход, настройки, управление пресетами,
    раскладка окна, фон, темы, «Переходить к следующему кадру».
    Неактивный пункт не срабатывает и по горячей клавише (`hk_fire`).
  - Панель правки без кадра неактивна целиком (`set_panel_live`):
    `enabled` ставится только корням разделов `st.sec_w` (и скрытых) —
    через `set_enabled` (обёртка `vgui.set_widget_enabled`: у HBox/VBox
    флаг не публичный). С 14.10.2026 отключённый контейнер vgui гасит
    ввод и вид всего поддерева, включая подписи, но собственные флаги
    детей не трогает. Поэтому при включении ничего пересинхронизировать
    не нужно: флажок объектива, кадрирование, фильтры, пятна
    остаются такими, какими их сделали свои `sync_*`. Аккордеон не трогается — разделы открываются и без
    кадра. Смена — только при смене состояния (`st.panel_live`).
  - Ряды «подпись | элемент» выключаются целиком, а не один элемент:
    ползунок панели — `set_slider_enabled` (ряд `slider_row` по
    `st.slider_rows`, ползунок без ряда — свой флаг; так ползунки
    фильтров и кисти в `sync_mask_ui`), «Своя w : h» кадрирования
    (`CropUi.c_row`), в окне экспорта «Качество JPEG» (`q_row`) и
    «Резкость на выход» (`sharp_row`).
  - Пересчёт — `sync_avail`: конец `open_file` (после `show_frame`),
    `on_load_done` (и ошибка), `close_file`, `refresh_history`,
    `sync_strip`, выделение в ленте (`on_select`, `select_all_frames`),
    `copy_settings`, `set_pair`, `rebuild_presets_menu`, конец main.
    Первый вызов — из `rebuild_presets_menu`, до панели: `sec_w` пуст —
    блокировка ждёт следующего (`st.panel_live` по умолчанию true, как
    `enabled` у новых виджетов). Тест — `avail_test.v` (корень раздела
    гасится, флаги детей целы).
- **Темы** (`themes.v`): все 15 тем vgui (тёмная, светлая, Monokai,
  Windows 10/11 и тёмные, KDE Breeze и тёмная, GNOME Adwaita и тёмная,
  macOS и тёмная, Mac OS X Aqua, Mac OS 9 Platinum) —
  меню «Вид — Тема» (флажки как переключатель), ключ в настройках.
  Смена на лету — `apply_theme`: `app.set_theme` (окно без явной темы
  перекрашивается само) + `paint_ui` — свои цвета vraw из палитры
  `Palette` (`make_palette(theme)`): фон области просмотра и ленты —
  `bg` темы, затемнённый (тёмная тема 25%, светлая 6%), правая панель —
  `panel_bg`, полосы сплиттеров — `border`, подписи — `text_primary`
  (текущий кадр, текущая запись истории) / `text_secondary` (имена
  кадров, записи, профиль объектива, подпись папки — `st.secondary_labels`)
  / `text_hint` (подсказки — `st.hint_labels`) / `text_disabled`
  (отменённые записи). Насыщенные цвета (подписи HSL `st.hsl_labels`,
  каналы кривых) в светлых темах затемняются на 35% (`Palette.hue`).
  Заглушка — `paint_placeholder(theme)`, гистограмма —
  `repaint_histogram` (см. «Гистограмма»). НЕ зависят от темы:
  холст и миниатюры (данные снимка), фон вокруг снимка
  (своя настройка). Виджеты со своими цветами надо регистрировать в
  этих списках State, иначе при смене темы они останутся старыми.
- **Масштаб интерфейса** (`uiscale.v`, 09.10.2026): `Window.set_ui_scale`
  vgui — шрифты, ползунки, кнопки крупнее/мельче, раскладка в логических
  пикселях. Только в «Настройки - Общие» — числом (Spinbox 50–300%,
  `ui_scale_min/max`; ни списка готовых значений, ни пунктов меню —
  решение Игоря 09.10.2026), применяется кнопкой «Применить» или Enter, НЕ на
  каждую цифру (при наборе «125» пришло бы «1», а окно настроек меняет
  размер под курсором); поле — 3 цифры, после применения в нём то, что
  применилось. Ключ `ui_scale` (%) в settings.json, `ui_scale_pct` — вне
  пределов (0 — старый файл) 100%. Тонкости:
  - `set_ui_scale` vgui держит ЛОГИЧЕСКИЙ размер окна и растягивает окно
    в s раз (1440 при 150% — за край экрана). `set_window_scale` сначала
    делит `config.width/height` на новый масштаб — окно на экране того же
    размера, и при запуске (окно 1440×890 физических), и на лету.
  - Лента кадров — доля вертикального сплиттера: логическая высота окна
    при масштабе s меньше в s раз, а подпись и поля ячейки — нет, и
    миниатюра сжималась в полоску. `scaled_strip_ratio` умножает долю
    ленты на отношение масштабов (пределы 0.05–0.6) — лента той же
    логической высоты; при запуске — от `strip_start_ratio`.
  - Диалоги берут масштаб главного окна при показе (`Dialog.show`,
    см. «Диалоги не больше экрана»); открытое окно настроек —
    `Dialog.refit` в `apply_ui_scale`.
  - «1:1» холста — логический пиксель: при масштабе 150% пиксель снимка
    — 1.5 пикселя экрана.
  - measure Spinbox vgui кладёт на кнопки 44 px, а они квадратные по
    высоте поля — число обрезалось: ширина поля задана явно.
- **Диалоги не больше экрана** (с 17.10.2026 — средствами vgui; до этого
  свой `dlgfit.v` с 09.10.2026): корень каждого диалога vraw (настройки,
  экспорт, окно «Экспорт», копирование настроек, пресеты) —
  `dialog_scroll(содержимое)`, ScrollBox с `fit_content` (размер по
  содержимому, а не 160 px). Размер окна при каждом показе считает
  `Dialog.show` vgui: по содержимому (окно пресетов — заданный при
  создании `presets_w×presets_h`), но не больше свободного места экрана
  родителя; не влезло по высоте — шире на полосу прокрутки, содержимое
  прокручивается. Если места хватает, ScrollBox растягивает содержимое на
  всё окно — flex работает как прежде. Смена масштаба при открытом окне
  настроек — `Dialog.refit`. Новый диалог — так же: `u.scroll =
  dialog_scroll(body)`, создать без размера и `d.show()`.
- **Настройки между запусками** (`settings.v`): `settings.json` рядом
  с программой (`app_dir()` — папка бинарника, vraw переносим) (json2) — `theme` (ключ из
  `theme_keys`), `ui_scale` (масштаб интерфейса, %), `viewer_bg` (ключ из `bg_keys`), `strip_open`,
  раскладка окна (`no_panel`, `no_strip`, `panel_left`, `strip_top`,
  `panel_order`, `panel_hidden`, `panel_w` — ширина панели, px — см.
  «Раскладка окна» и «Компоновка»),
  читаются в начале main, пишутся при изменении (`set_viewer_bg`,
  `set_strip_open`, `apply_theme`) атомарно (`write_atomic`: `.tmp` и
  переименование — сбой не оставит обрезанный файл); испорченный файл — значения по
  умолчанию (поля прежних версий — `ai_model`, `export_no_ai`,
  `no_ai_cache`, `fs_panel`, `fs_strip` — молча пропускаются, тесты
  `test_settings_old_ai_fields`, `test_panel_settings_roundtrip`).
  Старого места (`~/.config/vraw`) не читаем.

  без размера — по содержимому (колонки — `column_width`

- **Раскладка окна** (`panel.v`, 08.10.2026). Разделы правой панели —
  `panel_sections` (ключ, заголовок; порядок по умолчанию). При запуске
  все разделы свёрнуты, раскрытость не запоминается (18.10.2026). Виджеты секций создаются в main один раз (`panel_add` по
  ключу → `st.sec_w`), `layout_panel` пересобирает список секций
  аккордеона (`acc.sections.clear()` + add) по `settings.panel_order`
  без `panel_hidden`, сохраняя раскрытость (`st.sec_open`, по индексу
  `panel_sections`; показанные — `st.panel_keys`). Индекс секции
  «Градиентные фильтры» (`mask_ui.acc_idx`) ставит layout_panel (-1 —
  скрыта). Скрытый раздел только не виден: его настройки кадра
  действуют. `panel_order_from` (известные ключи без повторов,
  недостающий — новый — раздел за своим предшественником по умолчанию),
  `panel_keys_from` (скрытые и раскрытые из настроек), `panel_move` — чистые, тесты в `panel_test.v`.
  `layout_work` пересобирает корень (`st.root`: меню `st.menu` + рабочая
  область): `hsplit` с панелью справа или слева (половины и `min_*`
  меняются местами, `ratio` при смене стороны — `1 - ratio`, ширина
  панели сохраняется) или без панели — один `viewer`. Лента: скрыта
  целиком (`no_strip`) — `layout_strip` кладёт только `view_area`;
  сверху (`strip_top`) — половины `vsplit` наоборот (`strip_share` —
  доля ленты для `fit_strip_items`). Свернуть ленту до полосы — по-прежнему
  кнопка на полосе («Свернуть ленту»/«Развернуть ленту», `strip_open`).
  `center_strip` берёт долю просмотра `viewer_share` (без панели — 1).
  **Полноэкранный режим** (`set_fullscreen`, «Вид - Полноэкранный
  режим» F, выход F или Esc — последним в цепочке Esc, после отмены
  кадрирования и фильтров):
  `win.set_fullscreen`, полоса меню `visible = false` (остаётся в корне:
  с `MenuBar.keys_when_hidden` её сочетания клавиш работают и скрытой),
  `layout_work`/`layout_strip` при `st.fullscreen` кладут один снимок,
  поля `view_area` — 0 вместо `view_pad`. Панель и лента — общие для
  окна и режима (с 25.10.2026, просьба Игоря; раньше у режима были свои
  `fs_panel`/`fs_strip`): `no_panel`/`no_strip`, видимость —
  `panel_on`/`strip_on`. F8/F6, пункты меню и флажки окна настроек
  (блок «Окно и полноэкранный режим») — `set_panel_visible(st, v)`,
  `set_strip_visible(st, v)`: скрытое в окне скрыто и в режиме, и
  наоборот. Открыта папка без кадра
  (`load_folder`, `cur_path` пуст), а лента скрыта — показывается сама:
  иначе кадр не выбрать.
  Меню «Вид»: «Лента кадров» F6, «Обновить ленту» F5, «Лента сверху», «Панель инструментов»
  F8, «Панель слева» (`set_strip_visible`, `set_strip_top`,
  `set_panel_visible`, `set_panel_left` — пишут настройки и синхронизируют
  меню и окно настроек). Вкладка «Интерфейс» окна настроек: флажки
  панели и ленты, списки «Расположение панели/ленты», ряды разделов
  (флажок + вверх/вниз, `SecRow`, созданы один раз; порядок — пересборка
  `sec_box` в `sync_iface`, у крайних кнопки неактивны), «Как было».
- **Фон вокруг снимка** (`sync_view_bg`): выбранный цвет — фон
  `view_area`, только когда виден снимок; пока заглушка — цвет края её
  градиента (`Placeholder.edge`), чтобы вокруг не было рамки. Вызывается
  после `show_viewer`/`show_placeholder` и при выборе в меню.
- **Заглушка** (`Placeholder`, `make_placeholder(theme)`): Canvas 960×720
  с растяжкой (пассивный, `passive = true`) — радиальный градиент в цветах ТЕМЫ
  (`paint_placeholder`: края `theme.bg`, центр `theme.surface`,
  smoothstep, дизер), поверх Centered: значок 'aperture' (`text_hint`),
  заголовок (`text_primary`), подсказка (`text_secondary`), форматы
  (`text_hint`). От фона вокруг снимка не зависит. Текст по режиму
  (`set_placeholder_text`): без файла — «Откройте RAW-файл или папку»;
  папка открыта, кадр не выбран — «Выберите кадр / Двойной щелчок по
  миниатюре в ленте». `show_viewer()` — после первого превью кадра,
  `show_placeholder()` — при закрытии кадра.
- **Открыть папку** (`open_folder`): `close_file` (отмена загрузки,
  LibRaw закрыт, `file_gen++` — результаты воркеров отбросятся, буферы
  пусты, сайдкара нет, история пуста — правки некуда писать, `record`
  молчит, заглушка), затем `load_folder(dir, '')` — все RAW в ленте, ни
  один не открыт (`frame_idx = -1`, «N кадров»). Кадр открывается
  двойным щелчком. Нет RAW — предупреждение.
- **apply_pipeline()** — пайплайн в `cv.pixels` (stride 4) + `mark_dirty()`
  + гистограмма, однопоточно ~50 мс. Тональные ползунки (экспозиция,
  тени, контраст, насыщенность, «Тени/Света», EQ) применяют его ПО
  ОТПУСКАНИЮ: при драге on_change обновляет только
  `st.params` и подпись (`if !sl.dragging { apply }`), картинка — в общем
  on_release (общий паттерн `edit_slider`). Одиночные on_change (клавиши, «×»,
  сброс) применяются сразу. Никаких уведомлений отсюда.
- **Чекбоксы и кнопки** срабатывают по ОТПУСКАНИЮ мыши (так устроено в
  vgui: действие по `mouse_up` над виджетом, увод курсора отменяет клик).
  Тяжёлые обработчики («Коррекция объектива» ~0.6 с) не выполняются, пока
  кнопка зажата. Отдельного кода в vraw для этого не нужно.
- **Сообщения — тосты `vgui.NotificationManager`** (`nm`, левый верхний
  угол — над превью, панель не перекрывается), статусной строки и
  подсказки внизу окна НЕТ. `nm` добавляется в окно ПОСЛЕ корневого
  контейнера (`win.add_widget(top)`, затем `win.add_widget(nm)`):
  рисуется поверх, события получает первым. Открытие файла →
  `show_info('файл: превью WxH')`, итог экспорта — в его диалоге, а если
  диалог закрыт — `show_success`/`show_error`/`show_warning` (вид идёт
  из save_worker через `report(SaveOutcome, msg)`), ошибки проявки/открытия →
  `show_error`, «Сначала откройте RAW-файл» → `show_warning`.
  Notification сам держит перерисовку на время показа (авто-скрытие
  4 с, у ошибок 6 с) — needs_animation руками не нужен.
- **LibRaw — один раз на кадр**: превью проявляет загрузчик (loader.v),
  полный кадр — экспорт и 1:1. Перепроявки превью в окне нет (была только
  ради режима пересветов — `load_preview`, убран 06.10.2026).
- **Подготовка сырья — в фоне** (коррекция объектива, импульсы, шумодав,
  ореолы, маска; до ~3.5 с на превью). `prep_compute(PrepJob) PrepResult`
  — чистая функция без State/vgui: при `redo_lens` берёт копию
  `dev_linear` и корректирует объектив (результат → `raw_linear`), иначе
  копию `raw_linear`; дальше impulse → denoise → defringe → Capture-резкость
  (`deconvolve`, в новый буфер — он и есть `linear`) → `luma_masks` (по
  сырью до деконволюции).
  `request_prep(redo_lens)` снимает PrepJob (`make_prep_job`, копии
  буферов) и `spawn prep_worker` → результат через `app.post` в
  `st.prep_done` (главный поток): `take_prep` + apply. **Воркер всегда
  один**: запрос во время работы только меняет настройки (`lens_dirty`,
  nr-значения); prep_done сверяет их с применёнными (`nr_applied`) и при
  расхождении запускает ещё один проход — быстрые клики схлопываются.
  Capture-резкость сверяется так же: `dc_applied` — `dc_key(sharp)` (сила,
  радиус, порог; при силе 0 — нули) последней подготовки, `prep_stale`
  сравнивает и её.
  `st.corr` воркер делит с GUI, поэтому перед его освобождением (открытие
  файла, выход) — `wait_prep()`; результат дождавшегося воркера
  отбрасывается (`file_gen` сменился / `prep_running == false`).
  Пока воркер считает, тональные ползунки работают по старому `linear`.
- **Ползунки «Шумодав и ореолы»** («Импульсный», «Яркостный», «Цветовой»,
  «Ореолы», 0..100, step 1) — по отпусканию: при драге только
  подпись значения, пересчёт (request_prep, в фоне) — в on_release
  (`prep_fx`: только если `nr_applied != edit.nr`). «Сброс» их НЕ трогает (подготовка
  сырья, не тональная правка), у каждого своя кнопка сброса.
- vgui-грабля: `Label` рисует текст с внутренним отступом `pad = 4`
  сверху и слева, а контейнер отсекает детей по своей границе — ряд с
  подписью во вложенном VBox не меньше ~24 px (при 16 px низ букв
  обрезался).
- V-грабля: анонимная функция значением по умолчанию в поле
  `@[params]`-структуры даёт пустое выражение в C (`.progress = }`) —
  по умолчанию nil и подстановка внутри функции (`no_progress`).
- V: замыкание захватывает значения КОПИЕЙ, в т.ч. `mut`-захват int и
  массива (append в замыкании не виден снаружи) — счётчики по указателю
  на структуру.
- **Смена размера изображения в Canvas** (паттерн из `Canvas.load_from_surface`):
  присвоить `width/height/pixels`, вызвать `destroy_texture()`, `dirty = true`,
  `fit_to_view()`.
- **Пакетная установка ползунков** (откат истории, «Сброс», новый файл):
  `Slider.set_value()` САМ вызывает `on_change` (если значение изменилось),
  поэтому `set_edit()` выставляет все ползунки из `st.binds` под
  `st.suppress = true` — on_change только пишут значение и подпись, без
  пересчётов и записей в историю; пересчёт после — один (`restore_edit`).
