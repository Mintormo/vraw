# GUI: история правок и сайдкар

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Неразрушающее редактирование и история** (`history.v`). RAW не
  меняется; всё состояние правки — `EditState`: `params` (тональные;
  `params.curve` и `tc_*` — производные от `use_curve` и `curve_pts`),
  `curve_pts`, `lens_corr`, `use_curve`, `nr [4]f32`
  (импульсный, яркостный, цветовой, ореолы), `wb_mode/wb_temp/wb_tint`
  (баланс белого; `params.wb` — производная), резкость — `params.sharp`. Живёт в `st.edit`; из него
  же `make_prep_job`, `SaveJob`. `clone()` — глубокая
  копия (снимок не делит массивы с живым состоянием: `curve_pts[ch] = ...`
  меняет внешний массив на месте). Сравнение снимков — обычный `==`.
  - **Запись**: `record(mut st, key, name, merge)` после каждой
    завершённой правки (ползунки — в edit_slider, чекбоксы, кривая, «×»
    канала кривой, «Сброс»). Пропускается под `suppress`, без открытого
    файла и если снимок не изменился (отпустили на том же значении).
    Новая правка после отката отрезает «будущие» записи (`trim`).
    Склейка: одиночные шаги одного ползунка (колесо, клавиши — merge)
    подряд чаще 1.5 с (`hist_merge_ms`) заменяют последнюю запись, если
    она того же ключа (`key` = название ползунка) и последняя в списке;
    `hist_ms = 0` после перехода по истории запрещает склейку с чужой
    записью.
  - **Откат**: `goto_history(idx)` → `restore_edit(снимок)`: `set_edit`
    (ползунки из `st.binds` под suppress, чекбоксы `set_checked` — он
    on_change не зовёт, кривые + таблицы + редактор), затем пересчёт по
    необходимости: переключили коррекцию объектива → `request_prep(true)`, шумодав ≠
    `nr_applied` → `request_prep(false)`; и всегда apply (тон сразу, по
    текущему сырью). Записи при откате не удаляются — можно вперёд.
  - **Открытие файла** (кнопка и аргумент — общий `open_file`): без
    сайдкара `set_edit(neutral_edit())` — ВСЕ настройки нейтральные (в
    т.ч. шумодав, объектив вкл), затем проявка, камерная
    кривая и `start_history` — первая запись «Открыт файл». С сайдкаром —
    см. ниже.
  - **Сайдкар** (`sidecar.v`): `IMG_0991.CR3.vraw.json` рядом с RAW.
    **Версия 2** (с 01.11.2026; пишет `encode_history` вручную, не json2):
    вторая строка — `"app": "vraw", "version": 2, "rating", "flag",
    "current"` (лента читает только начало файла), затем `state` —
    текущие настройки, `history` — по записи на строку: `{"name", "key"
    (если не пусто), "state"}`. Настройки — `SideState` через json2.Any:
    только поля, отличные от `side_defaults()` (`side_sparse`; нетронутый
    снимок — `{}`), числа — до 6 значащих цифр (`round_sig`: 1.5500001 →
    1.55), точки кривых — парами `[x, y]` (`side_obj`), JSON одной
    строкой — `any_line`. Каждая запись хранит настройки целиком, а не
    разницу с предыдущей (испорченная запись не тянет за собой
    остальные). `side_defaults` — умолчания ФОРМАТА, менять нельзя (сейчас
    = `side_state(neutral_edit())`, тест `test_sidecar_v2_compact`); новое
    поле — со значением, которое старые файлы подразумевают. Чтение
    (`decode_sidecar`): json2.Any → проверка app/версии → v2 —
    `side_from_obj` (умолчания + поля файла → снова текст → `SideState`;
    `json2.decode_any` вложенные массивы структур теряет), v1 —
    `decode_sidecar_v1`. На сайдкарах Игоря: 438 КБ → 19 КБ (14 файлов,
    в 15–30 раз меньше), чтение 1–9 мс — не медленнее v1.
    **Версия 3** (13.11.2026, `sidecar_strokes.v`) — мазки кисти один раз:
    таблица `"strokes"` (мазок на строку) между шапкой и `state`, в
    настройках фильтров и частей `"strokes": [0, 1, ...]` — номера в ней.
    В v2 каждая запись повторяла все мазки на свой момент — рост
    квадратичный: 100 мазков по 80 точек — 14.6 МБ и 1.9 с записи в
    главном потоке на каждую правку, чтение 1.3 с; в v3 — 352 КБ, 47 мс
    и 30 мс. Запись (`state_line`): снимок без мазков (`bare_mask`) идёт
    обычным путём (`side_sparse`), номера мазков подставляются
    (`StrokeTable.index`: сначала по адресу точек — снимки делят массивы,
    — иначе по тексту `stroke_line`; каждый мазок через json2 — один
    раз). В таблице только мазки, на которые ссылаются записи: отрезанное
    отменой уходит. Без мазков файл пишется версией 2 (его читает и
    прежний vraw). Чтение (`state_of_obj`): номера вынимаются
    (`take_refs`, вне таблицы — ошибка «испорченная история»), снимок
    разбирается без них, затем мазки таблицы ставятся по номерам
    (`put_refs`) — один мазок на все записи и в памяти. Мазки целиком (v2,
    v1) тоже читаются; после чтения одинаковые мазки записей сводятся в
    общие массивы (`share_strokes`). **Текущие настройки без истории** —
    `load_side_current` / `decode_side_current`: разбирается только
    начало файла до строки `"history"` (шапка, таблица, `state`);
    версия 1 или другая разметка — полный разбор. Им пользуются
    миниатюры (`thumb_geom`, `side_thumb_edit`), пакет (`batch_items`),
    сравнение (`pair_side_edit`), предзагрузка. Тесты
    `sidecar_strokes_test.v`.
    **Версия 1** (до 01.11.2026) — `SideFile` (`app`, `version`, `rating`, `flag` — пометка
    отбора, `current`, `state` — текущие настройки, `history` из
    `SideEntry`; пометка и `current` с 03.10.2026 стоят до настроек —
    json2 пишет поля по порядку), настройки в каждой записи — все поля
    `SideState`, json2 с отступом 2; читается, при первой правке файл
    перезаписывается версией 2. Тесты старого формата берут текст v1 от
    `side_v1_text` (хелпер в `edit_test.v` и `rating_test.v`).
    `SideState` — только исходные значения (точки кривых
    `[][]vgui.CurvePoint`, массивы списками; имена полей — ключи JSON,
    менять нельзя; значений по умолчанию в структуре нет — `[][]T{len: 4, init:
    ...}` в поле ломает C-кодоген V внутри json2). Перевод EditState ↔
    SideState — `side_state`, `edit_state` (с `validate` — размеры
    массивов). `decode_sidecar` отвергает чужой
    файл, новую версию, испорченную историю и массивы. Камерная кривая в
    файл не пишется (её писали для убранного CLI) — кадр считает её при
    открытии; поле `camera_curve` старых сайдкаров json2 пропускает
    (тест `test_sidecar_legacy_camera_curve`). Поля ББ и резкости
    (`wb_mode`, `wb_temp`, `wb_tint`, `sharp_*`, `sharp_rgb`, `dc_*`) в
    старых файлах отсутствуют: «как снято», резкость выключена, радиус 0
    читается как 1, радиус деконволюции 0 — как 0.75, её порог при нулевой
    силе — как 10 (тест `test_sidecar_wb_sharp_fields`). Кадрирование:
    `rot90`, `flip_h`, `flip_v`, `angle`, `crop` (x0, y0, x1, y1; пусто —
    весь кадр; проверка с допуском 0.001 — доли у края 1 ± погрешность
    f32 — и обрезка к 0..1), `crop_aspect`, `crop_aw/ah`, `crop_portrait`
    (нули старых файлов — 3:2; тест `test_sidecar_crop`). Поля размера на
    выход (`size_mode`...) сайдкаров 30.09 json2 пропускает — размер
    теперь в окне «Экспорт».
    **Запись** — `sync_sidecar` в конце `record` и `goto_history`:
    атомарно (`.tmp` + `os.mv`); без правок (одна запись «Открыт файл»)
    и без пометки отбора файл не создаётся, существующий обновляется всегда; ошибка записи —
    `show_warning` один раз на файл (`side_err`, `st.nm`). **Чтение** в
    `open_file`: снимок `current` выставляется ДО проявки превью
    (объектив — в синхронную подготовку), но с нулевым
    шумодавом — его досчитает фоновый `request_prep` из `restore_edit`,
    открытие не замирает на секунды. После `setup_curve` снимкам из
    файла заполняются производные поля (`with_derived` по камерной
    кривой кадра) — иначе `record` считал бы любое отпускание правкой.
    Испорченный файл — предупреждение в тосте открытия, при следующей
    правке он перезапишется. `set_edit` тоже строит производные поля
    через `with_derived`.
  - **Очистка истории** (01.11.2026, просьба Игоря; `clear_history`,
    history.v): значок `eraser` в ряду «До» под списком («Очистить историю:
    удалить все правки кадра»), с вопросом (`message_box`, по умолчанию
    «Отмена»). Все правки удаляются: переход к «Открыт файл»
    (`goto_history` - превью и подготовка сырья, как двойной щелчок), в
    истории остаётся только она, сайдкар перезаписывается без правок,
    `ba_ref` = 0. Лента: `edited` = false и `push_live_thumb` - миниатюра
    исходного вида без отметки (`draw_mark` только рисует поверх, а
    `update_live_thumb` при позиции 0 на ленту не выкладывает). Кнопка
    активна при записях больше одной (`history_clearable`,
    `refresh_history`). Тест `test_clear_history` (edit_test.v); в окне -
    многоугольник и автотон сняты, отметка «изменён» ушла.
  - **«Сброс»** — тональный: снимок с `Params{}` и диагональными кривыми
    (объектив, камерная кривая, шумодав остаются) через
    `restore_edit` + запись «Сброс» — отменяется Ctrl+Z.
  - **Секция «История»**: `vgui.ListBox` (item_height 22, одна колонка без
    заголовка — `add_column` включает заголовок, `show_header = false`
    после; ячейки-виджеты вертикальный список рисует только по колонкам).
    Строки — `vgui.label` «N. название», отменённые — серые
    (`hist_future_color`); `refresh_history` перестраивает список,
    выделяет текущую и прокручивает к ней (ensure_visible у ListBox
    приватный — считается вручную). **Одиночный щелчок (и стрелки)
    только выделяет запись**, переход — двойной щелчок или Enter
    (`on_dbl_click`) → `goto_history`; текущая запись — жирная и ярче
    (`hist_current_color`), выделение может стоять на другой. Горячие
    клавиши окна: Ctrl+Z — назад, Ctrl+Shift+Z и Ctrl+Y — вперёд.
  - **Тест** `edit_test.v` — без окна: виджеты vgui работают без
    App, а пересчёты на пустом State сразу выходят. Проверяет: драг —
    одна запись, склейку шагов, откат/возврат/отрезание будущего,
    глубину снимков кривых, чекбоксы; сайдкар — не создаётся без
    правок, запись/чтение всей истории и позиции (снимки совпадают),
    отсутствие ложных записей после загрузки, отказ на испорченном и
    чужом файле и неверных размерах массивов (файлы — во временной
    папке). Запуск:
    `~/soft/v/v -cc gcc test .` (все тесты).
