# GUI: экспорт

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Сохранение — в фоновом потоке** (`save_worker` в `spawn`):
  `develop_full` (`export.v`: LibRaw полного размера → объектив
  (`correct_lens`) → импульсы → шумодав → ореолы → Capture-резкость
  (свой буфер, по нему и карта дымки) → маска (по сырью до неё) →
  `apply_image` по `e.params` — ББ и резкость в нём же) → `imgio.write` в формате `job.format`.
  **Память экспорта** (05.10.2026): LibRaw закрывается сразу после
  `develop` (метаданные — до этого): его сырьё и 4-канальный кадр
  (~240 МБ) не живут весь экспорт; промежуточные результаты — в
  `bigbuf` через варианты `_into` (`luma_masks_into`,
  `deconvolve_into`, `geom_apply_into`, `haze_map_big` + `HazeMap.free`)
  и освобождаются, как только не нужны (сырьё — после Capture или
  геометрии, выход Capture — после геометрии, маска до геометрии — после
  её поворота); `defer` в `develop_full` страхует ранние выходы (повторный
  free безвреден). `Image.rgb` — тоже bigbuf (после ресайза — обычный),
  вызывающий освобождает `Image.free()` после записи (`save_worker`,
  `batch_frame_run`). Маска «Тени/Света» — до Capture-резкости (как в
  превью: по сырью после шумодава). Превью зовёт прежние функции —
  результат в обычном массиве сборщика. Замер (24 Мп, шумодав, обе
  резкости, дымка, поворот; три экспорта подряд): пик ~1.0 ГБ (было
  2.1–2.4), RSS после экспорта ~70 МБ (было 1.75–2.05 ГБ, рос), куча
  сборщика 61 МБ. Воркер независим от GUI: свой
  `raw.open` внутри `develop_full` (st.dev может смениться, пока он
  работает), профиль — в общей базе lensfun (только чтение); вход —
  `SaveJob` (`edit: st.edit.clone()` — настройки с производными полями:
  таблицы кривых и камерная кривая, как в окне; копия по значению;
  формат, путь и размер (`size: settings.export_size_opts()`) — из окна
  «Экспорт», качество — `settings.jpeg_quality`), выход —
  `report(mut app, on_done, SaveOutcome, msg)` → `post_result` (post.v).
  Хендлы потоков — в `State.save_threads` (`[]Worker`, workers.v), `wait_all` после `app.run()`,
  чтобы закрытие окна не оборвало запись файла. Ровно ОДИН `wait()` на
  поток: повторный (был при переходе на общую базу lensfun) — аварийное
  завершение «V thread join failed: 3» при закрытии после экспорта.
  Закрытие окна во время ПАКЕТА (`st.exp.n > 1`, 13.11.2026) выставляет
  `cancel`: без окна пакет шёл бы невидимо до последнего кадра; отмена —
  между этапами, начатая запись файла дописывается. Одиночный экспорт
  дожидается целиком.
- **Этапы и отмена экспорта** (`export.v`): `ExportStage` (демозаика,
  объектив, импульсы, шумодав, ореолы, Capture-резкость, тон и цвет,
  запись файла —
  в диалоге «Запись PNG», для GIF «Палитра и запись GIF»).
  `develop_full(path, e, db, ExportOpts{progress, ...})` зовёт
  `progress(этап, 0, 0)` в начале каждого этапа (done/total — доля
  этапа; с AI-шумодавом были плитки, сейчас всегда 0, 0); false —
  отмена, ошибка `ExportCancelled`. Этап `.write` сообщает save_worker
  перед `imgio.write`. `export_plan(e, fmt)` — какие этапы пройдут
  при этих настройках (условия — как в `develop_full`, менять вместе) и
  их веса: примерные секунды на 24 Мп (демозаика 0.6, объектив 2.8,
  импульсы 4, шумодав 4, ореолы 2, Capture-резкость 2.6,
  тон 1.6, запись —
  `write_secs(fmt)`: JPEG 0.7, PNG 4.1, TIFF 3.4, BMP 0.1, QOI 0.35,
  GIF 1.4).
- **Окно «Экспорт»** (`export_setup.v`, 01.10.2026; «Файл - Экспорт...»
  Ctrl+E, пока экспорта нет — иначе диалог прогресса): `vgui.Dialog`
  без размера — по содержимому (колонка подписей `lbl_col` —
  `column_width` по всем подписям + 8, поля Label), создаётся при первом открытии, закрытие прячет, тема — как у
  окна настроек (`apply_theme` → `paint_export_setup`). Все поля пишутся
  в `Settings` сразу (`export_setup_changed` → `save_settings` +
  `sync_export_setup`) — их же возьмёт пакетная обработка: папка
  (`export_dir_mode` 'raw' — рядом с RAW / 'dir' — `export_dir`; выбор
  «Выбранная папка» без папки сразу открывает выбор, отказ — остаётся
  'raw'; «Выбрать...» — `native_select_folder_dialog` со стартом в
  текущей; путь — `PathNote`), шаблон имени (`export_name`; переменные
  английские: `{name}` — имя RAW без расширения, `{num}` — номер в
  экспорте `NameInfo.num` с нулями до max(3, цифр `count`), `{date}` —
  дата съёмки `NameInfo.shot` «2026-09-28»; `export_file_name`:
  `/\:*?"<>|` → «_», пустой результат — имя RAW; Enter в поле —
  «Экспорт»; старый `{имя}` переводит `name_tmpl_migrate` при загрузке
  настроек). Дата — `raw.Meta.shot` (LibRaw `other.timestamp`, EXIF
  через mktime — `time.unix(shot).local()` даёт часы камеры; нет — дата
  изменения файла); `export_path_taken` открывает RAW (`raw_shot`,
  единицы мс) только если `{date}` в шаблоне. Номер — у пакета индекс
  кадра + 1 (координатор), у одиночного экспорта 001. «Если
  файл есть» (`export_exists`: 'number' — `export_path` подбирает
  «имя-2», «имя-3»…; 'overwrite'), формат (`fmt_title`), качество JPEG
  (`jpeg_quality`, у других форматов выключено), флажок «16 бит» в ряду
  формата (`export_8bit`, отрицание — по умолчанию TIFF и PNG пишутся в
  16 бит; у JPEG, BMP, QOI, GIF снят и выключен; `Settings.export_bits16(f)`
  → `ExportOpts.bits16` → `Image.bits16` → `WriteOpts.bits16`; в итоге
  экспорта — «…, 16 бит»), размер
  (`export_size`: '' как есть, 'long' — `export_long`, 'fit' — вписать в
  `export_w × export_h`, 'pct' — `export_pct`; ряд пересобирается под
  режим — скрытые виджеты место занимают; `export_dims`: только
  уменьшение, длинная сторона ровно по заданию, короткая — пропорцией),
  резкость на выход (`export_sharp`: '' нет, 'low' / 'std' / 'high' —
  `export_sharp_amounts` 0.4 / 0.8 / 1.3 в `ExportSize.sharp`; один
  список вместо флажка и ползунка; при размере «Как есть» список
  выключен — кадр не уменьшается, резкость кадра уже есть; в итоге
  пакета — «…, резкость: средняя», `size_desc`; окно стало 680×680),
  ряд «Метаданные»: флажок «Сохранять EXIF» (`export_no_exif`, отрицание
  по той же причине) и поле копирайта (`exif_copyright`, пусто — тега
  нет; выключено без EXIF); запись — `write_image` (`export.v`: EXIF по
  `Image.meta` — `develop_full` возвращает метаданные кадра —
  `export_exif`: модель полная «Canon EOS R8», дата съёмки — часы камеры,
  дата записи — сейчас), им пишут и `save_worker` (`SaveJob.settings`), и
  пакет; окно стало 680×740 (флажок AI-шумодава убран 19.10.2026).
  Внизу итог «IMG.jpg · 2048 × 1365
  px» (`sync_export_result`: `crop_size` по полному кадру →
  `export_dims`). «Экспорт» (`export_confirm`): имя из поля, папки нет —
  ошибка тостом, иначе окно закрывается и `st.export_go(path, fmt)`
  (замыкание в app.v: `ExportCtl`, `SaveJob`, `save_worker`).
  Размер на выход — настройка экспорта, не кадра (был в секции
  кадрирования и сайдкаре 30.09 — поля старых сайдкаров json2 пропускает).
  Тесты (`export_test.v`): `export_dims`, `export_file_name`,
  `export_path` (номера, перезапись, своя папка), значения по умолчанию.
- **Пакетный экспорт** (`batch.v`, 01.10.2026). В окне «Экспорт» ряд
  «Кадры» (`set_export_targets` при каждом открытии; выбор не
  запоминается): 'open' — открытый кадр, 'sel' — выделенные в ленте
  (если больше одного — по умолчанию), 'all' — вся папка
  (`export_target_paths`); итог — «12 кадров: IMG.jpg... · длинная
  сторона до 2048 px». Не 'open' → `st.export_batch(paths)` (app.v):
  `batch_items` — открытый кадр (путь по `st.side_path`) с `st.edit`
  (производные поля уже есть, `derived`), остальные — состояние из
  сайдкара или `neutral_edit` (сайдкар не читается — кадр нейтрально +
  предупреждение). `batch_worker` —
  координатор: кадры потокам `batch_frame_job`, одновременно не больше
  `load_level(settings.export_load).par` и не больше, чем помещается в
  свободную память: `mem_par(par, frame_pixels(первый кадр),
  mem_available())` — `MemAvailable` из /proc/meminfo минус 512 МБ на
  пик кадра `export_bytes_per_px` = 44 байта на пиксель (24 Мп ~ 1 ГБ),
  минимум один; итоги кадров — по
  каналу `chan BatchDone` в `BatchTally`, в конце `wait()` всех потоков
  (ровно один раз). Пути — `export_path_taken` в координаторе с картой
  занятых (одновременные кадры IMG.CR3 и IMG.DNG иначе получили бы один
  файл; при перезаписи — тоже номер). События в главный поток —
  `BatchEvent` (start: имя, путь, план; stage: этап; end) через
  `app.post` → `batch_event` (`ExportCtl.frames` — кадры в работе,
  `finished`). `batch_derive` для неоткрытого кадра:
  свой `raw.open`, `cam_color`, при `use_curve` или коррекции объектива —
  проявка half-size, `cam_jpeg`, `lens_match` (сила виньетки и масштаб по
  профилю — всегда), `correct_lens` профилем (если включён) и ручной
  `e.lman` (всегда, если задана; до 13.11.2026 ручная здесь не
  применялась и кривая чуть расходилась с окном), `camera_look` (как загрузчик:
  A.jpg из окна и B.jpg пакетом из копии того же CR3 совпали до
  пикселя), затем `with_derived`; `develop_full(size)` → `imgio.write`.
  Ошибка кадра — в список, пакет идёт дальше; отмена (`ctl.cancel`) —
  весь пакет. Итог — `batch_outcome`: «Экспорт: сохранено 12 из 12
  кадров - JPEG, 3 мин 05 с» (.saved), с ошибками — первая и «и ещё N»
  (.failed), отмена — «Экспорт отменён: сохранено 5 из 12» (.cancelled).
  `fraction()` пакета — (готовые + Σ `plan_fraction` кадров в работе) / n;
  диалог: «Готово 4 из 12 кадров · нагрузка: обычная», этап — один кадр
  в работе: «IMG.CR3: Шумодав», несколько — «В работе 2 кадра: A, B»
  (`batch_stage_text`). Экспорт доступен и без открытого кадра.
  **Нагрузка** (`load_keys`/`load_names`/`load_notes`, `LoadLevel`):
  'low' — 1 кадр, nice 19, `omp_set_num_threads(cpus/4)`; 'normal' — 2
  кадра, nice 10; 'high' — 3, nice 0. `apply_load` в начале каждого
  потока экспорта (координатор, кадры, `save_worker` — `SaveJob.load`):
  `setpriority(PRIO_PROCESS, gettid())` — только этот поток, его потомки
  (деконволюция, резкость, OpenMP LibRaw) наследуют; повысить без прав
  нельзя — главный поток не трогать. Замер (-prod, 3 кадра CR3, шумодав): по одному 9.4 с, по два
  6.7, по три 4.7; в окне 5 кадров: 15.2 / ~8.5 / 6.9 с. Потоки
  `disk$0`/`traceq0` с nice 19 — драйвера графики, не наши.
  Тесты (`batch_test.v`): итог, `batch_items` (открытый, сайдкар, нет
  сайдкара, испорченный), `batch_derive` на тестовом CR3,
  `export_path_taken`, `load_level`, `apply_load` (nice только своего
  потока), доля пакета.
- **Диалог экспорта** (`export_ui.v`, `vgui.Dialog` 560×250, модальный,
  создаётся при первом экспорте, закрытие прячет, тема — как у окна
  настроек, `apply_theme`): «IMG.CR3 -> out.jpg», папка (`PathNote`),
  «Этап 3 из 6: Шумодав», полоса и %, «прошло 12 с · осталось ~40 с»,
  кнопка «Отменить» / «Закрыть». `ExportCtl` (`st.exp`, nil — экспорта
  нет): `cancel` (`Flag`, workers.v — атомарно: `set` / `is_set`) ставит главный поток, читает воркер; этап и доля этапа —
  главный поток
  (`st.exp_progress` из `export_progress_fn` через `app.post`).
  Доля — `fraction()`: веса пройденных этапов + доля текущего.
  Оставшееся время — экстраполяция прошедшего по доле (с 15% и 2 с). Экспорт идёт, пока диалог закрыт;
  «Экспорт...» в это время открывает диалог, а не второй экспорт.
  Итог (`export_finished`) — в строке времени открытого диалога («Готово»,
  формат, размер, МБ, качество (только JPEG), секунды; ошибка — красным), в закрытом — тостом.
