# GUI: копирование настроек и пресеты

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Копирование настроек и пресеты** (`presets.v`).
  - **Группы** (`copy_groups`, названия `copy_group_names`):
    `tone` — экспозиция, тени, контраст, текстура, чёткость, тон-эквалайзер, «Тени/Света»,
    камерная кривая (вкл/выкл); `color` — баланс белого
    (режим, температура, оттенок), сочность, насыщенность; `curves` —
    точки кривых; `hsl`; `nr` — шумодав и ореолы;
    `sharp`; `haze`; `lens`; `crop` — геометрия, пропорция,
    размер (по умолчанию не отмечена: `default_copy_groups`, как в
    Lightroom). `merge_groups(dst, src, groups)`
    берёт из src только исходные поля групп; производные (таблицы кривых,
    камерная кривая, матрица ББ) пересчитывает `set_edit`
    (`with_derived`), в сайдкар они не идут. Новая настройка кадра должна
    попасть в одну из групп — иначе её не скопировать.
  - **Окно групп** (`GroupsUi`, `show_groups(preset)`, `vgui.Dialog`
    440×466 (9 групп), создаётся один раз, тема — в `apply_theme`): флажки групп
    (последний выбор — `settings.copy_groups`, нет в файле — все), «Все»,
    «Ничего», «Отмена», главная кнопка. Два режима: копирование и
    «Сохранить пресет» с полем имени (Enter — сохранить); содержимое
    пересобирается под режим (`layout_groups`: clear + add — скрытый
    виджет в VBox место занимает). Без открытого кадра — предупреждение.
  - **Буфер** — `st.clip` (копия `st.edit`) и `st.clip_groups`: свой, не
    системный буфер обмена; живёт до выхода.
  - **Вставка** (`paste_settings`, через `st.paste_fn` из main — ей нужны
    холсты и тосты): цели `paste_targets` — выделенные в ленте, если их
    больше одного, иначе открытый кадр (без него — выделенный). Открытый
    кадр — `restore_edit` + `record` (обычная правка, Ctrl+Z отменяет);
    прочие — `paste_to_file`:
    история из сайдкара (нет — «Открыт файл» с `neutral_edit()`),
    слияние с текущим снимком, отрезание «будущего», новая запись,
    `write_atomic`; те же настройки — без записи; испорченный сайдкар не
    трогается (ошибка в тосте). Отметка «изменён» — `mark_frame_edited`.
    Тост: «Вставка настроек: N кадров из M».
  - **Пресеты**: `presets/<имя>.json` рядом с программой
    (`presets_dir()`, как settings.json и models/) — `PresetFile`
    (`app: vraw-preset`, `version`, `name`, `groups`, `state` — SideState
    всего кадра, применяются только группы). Имя файла —
    `preset_file_name` (запрещённые в Linux/Windows символы → «_»);
    одноимённый перезаписывается («обновлён»). Меню — `rebuild_presets_menu`
    через `MenuBar.set_items` (vgui) после любого изменения папки; оно же
    обновляет список открытого окна управления (`fill_presets_ui`).
    Применение — `apply_preset` → `paste_fn`, запись «Пресет: имя».
  - **ББ в пресете — числом или сдвигом** (с 24.10.2026). Флажок окна
    сохранения «Баланс белого сдвигом от «как снято»» (`GroupsUi.wb_shift`,
    только в режиме пресета; последний выбор — `Settings.preset_wb_shift`).
    Сдвиг — `WbShift` (`on`, `mired` — разница майред 1e6/K, минус теплее:
    одинаковый на глаз сдвиг при любом свете; `tint` — разница оттенка),
    считается `wb_shift_of` от «как снято» открытого кадра (`st.shot_temp/
    tint`; «как снято» — нулевой сдвиг) и едет в `EditState.wb_shift` (в
    сайдкар и историю не пишется). Файл — `preset_file`: со сдвигом и
    группой `color` — `version: 2`, `wb_shift`, `wb_mired`, `wb_dtint`
    (в `state` ББ исходного кадра — для справки); без них — `version: 1`,
    такие пресеты читают и старые vraw, а со сдвигом старый vraw
    откажет («версия новее»), а не применит чужую температуру числом.
    `load_preset` поднимает сдвиг (NaN — 0, пределы ±500 майред,
    ±2·wb_tint_max), `import_preset` его сохраняет. Вставка — в
    `paste_settings` через `src_for_frame`: со сдвигом и группой `color`
    открытый кадр берёт `st.shot_temp/tint`, остальные — `file_as_shot`
    (только заголовок RAW, `raw.open` + `cam_color().as_shot()`; нет
    файла — ошибка кадра в тосте). `wb_apply_shift` — режим «Свой»,
    температура округлена до 1 K и зажата в `wb_temp_min..max`, оттенок —
    в ±`wb_tint_max`; нулевой сдвиг — «как снято». Тесты
    `test_wb_shift_math`, `test_preset_wb_shift_file`,
    `test_paste_wb_shift`, `test_file_as_shot` (CR3 — `VRAW_TEST_CR3`).
  - **Окно «Управление пресетами»** (`PresetsUi`, `show_presets` через
    `st.show_presets` из main, `vgui.Dialog` 560×400, создаётся один раз,
    тема — в `apply_theme`): список (`ListBox`), справа «Удалить»,
    «Экспорт...», «Импорт...», «Экспорт всех...», внизу поле «Имя» и
    «Переименовать», «Закрыть». Папка перечитывается при каждом открытии
    окна (файлы можно класть и удалять руками — отдельного «Обновить
    список» нет: у MenuBar vgui нет события открытия меню). Без выбора
    кнопки пресета погашены; выбор после пересборки — на том же имени,
    иначе на той же строке (после удаления — соседний).
    Переименование — `rename_preset` (Enter в поле, двойной щелчок по
    строке ставит фокус в поле): файл переименовывается (`os.mv`), поле
    `name` обновляется, настройки как есть; чужой файл/новая версия,
    пустое или занятое имя — предупреждение; смена только регистра — тот
    же файл (Windows/macOS). Удаление — `vgui.message_box` поверх окна
    («Удалить» / «Отмена», Enter и Esc — «Отмена»), `delete_preset`.
  - **Импорт и экспорт** (кнопки окна управления; системные диалоги — в
    замыканиях `st.import_presets`/`st.export_presets` из main, им нужны
    окно и App): «Импорт...» — несколько .json за раз,
    `import_preset` проверяет файл как `load_preset` (чужой — ошибка в
    тосте) и перезаписывает его в `presets/` (имя — из поля `name`, без
    него — имя файла); «Экспорт...» — копия выбранного файла как есть
    через диалог сохранения; «Экспорт всех...» — в выбранную
    папку. Чужой файл с тем же именем не затирается: `free_path` даёт
    «имя (2).json», а файл с тем же содержимым считается тем же
    (повторный импорт/экспорт копий не плодит).
