# GUI: лента кадров

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

- **Браузер папки** (`browser.v`): лента миниатюр всех RAW папки
  открытого кадра под просмотром. `open_file` берёт `os.real_path` и в
  конце зовёт `show_frame`: папка сменилась — `load_folder`
  (`scan_folder`: расширения `raw_exts` без учёта регистра, не папки, по
  имени), затем выделение, прокрутка к кадру (`sync_strip`, вручную —
  ensure_visible у ListBox приватный) и подпись «папка · N из M».
  - **Подпапки** (30.10.2026): `settings.strip_subdirs` + `subdir_depth`
    (1..`subdir_depth_max` = 9; 0 в файле — `subdir_depth_default` = 1),
    «Настройки - Интерфейс - Лента кадров» (флажок и Spinbox, одна
    цифра — `on_change` при наборе уже итоговый; `set_strip_subdirs` —
    запомнить и `refresh_folder`; кадр из подпапки, выпавшей из ленты, —
    `show_frame` грузит его папку). `scan_folder(dir, depth)`
    (`strip_depth(settings)`, 0 — только папка): сначала файлы папки,
    потом подпапки по имени, рекурсивно; скрытые (с точки) и ссылки на
    папки — мимо (круги, повторы). `show_frame` перезагружает ленту,
    только если кадра в ней нет (открытие кадра из подпапки ленту не
    меняет). `frame_subdir(folder, path)` — подпапка кадра: в подсказке
    ячейки (`cell.tooltip`) и в подписи над лентой («папка/подпапка ·
    N из M»). Памяти — ~200 КБ пикселей холста на кадр: большое дерево
    с большой глубиной даёт тысячи ячеек.
  - **Лента** — `vgui.list_box_h` (горизонтальный ListBox); элемент —
    ячейка из запаса (`strip_cell`, переиспользуется при смене папки —
    см. «Замыкания и память»), VBox: Canvas миниатюры (flex, `stretch = false` — вписывание с
    сохранением пропорций, `passive = true` — щелчок уходит в список (не `enabled = false`: с 14.10.2026 vgui рисует такой холст с вуалью),
    зум/панорама выключены) + подпись имени (12 px). Колесо крутит ленту
    по наведению, без фокуса; щелчок колеса — один кадр
    (`scroll_x_speed = item_width`, и в `fit_strip_items`); у края
    лента останавливается, колесо не уходит дальше. **Одиночный
    щелчок (и ←/→ при фокусе на ленте) только выделяет** миниатюру;
    открыть кадр — двойной щелчок или Enter (`on_dbl_click` ListBox
    зовётся на оба) → `goto_frame` → `open_file`; не открылся —
    выделение возвращается на текущий. Поскольку выделение может стоять
    на другом кадре, у редактируемого подпись жирная и ярче
    (`Frame.name`, `sync_strip`). Горячие клавиши окна
    ←/→, Home/End — соседний/первый/последний кадр (если фокус у
    ползунка, его стрелки двигают значение — hotkeys окна срабатывают
    только для необработанных клавиш). Колесо прокручивает ленту, когда
    у неё фокус (так устроен ListBox).
  - **Миниатюры** — `make_thumb(path, g)`: свой `raw.open` (воркер не делит хендл с
    GUI), `thumb_min(thumb_w)` (у CR3 — 1620×1080), `raw.decode_jpeg`
    (libjpeg, буфер вне сборщика — с 13.11.2026; stbi держал в куче полный
    JPEG у форматов без малого превью, 72 МБ на 24 Мп), `fit_thumb`:
    поворот по flip + вписывание в буфер RGBA `thumb_w × thumb_h`
    (276×184, 3:2, вдвое больше ячейки — для HiDPI) усреднением по блоку,
    поля `thumb_bg`. С кадрированием и поворотом: `g` — `thumb_geom`
    (сайдкар кадра → `out_geom`; читается только начало файла —
    `load_side_current`, без истории), превью камеры в ориентации кадра →
    `geom_rgba` во всю величину обрезки → `fit_thumb` (усреднение);
    картинка больше `thumb_geom_max` (1620 px по длинной стороне) сначала
    уменьшается до него — промежуточные буферы не в сотни МБ.
    **Правки на миниатюрах** (24.10.2026). Открытый кадр с правками
    (`hist_pos > 0`) — из его превью: `apply_pipeline` после чистого
    результата (до подсветок клипа, маски, до/после; не в кадрировании —
    там превью без обрезки) зовёт `update_live_thumb` — `thumb_from_rgba`
    (вписывание как у `fit_thumb`, по блоку — среднее до 4×4 точек,
    доли мс) в `st.live_thumb` (`live_gen` = `file_gen`) и
    `push_live_thumb` на холст кадра (новый `thumb_seq` — фоновые
    результаты этого кадра её не перекроют; `Frame.live`). Миниатюра
    меняется по ходу правки, в том числе при живом перетаскивании. Первый
    шаг правки пересчитывается до `record` (hist_pos ещё 0) —
    `sync_thumb` после записи сайдкара снова зовёт `push_live_thumb`;
    откат к «Открыт файл» — снова JPEG камеры (`refresh_thumb`).
    `open_frame_ok` — открытый кадр стоит в ленте под `frame_idx` (при
    смене файла индекс обновляется позже первого пересчёта). Остальные
    правленные кадры (`Frame.edited` по началу сайдкара): `thumb_worker`
    после быстрого прохода по JPEG камеры вторым проходом (кроме
    открытого) проявляет их с пониженным приоритетом (`apply_load`,
    `pf_nice`): `side_thumb_edit` (настройки сайдкара при current > 0) →
    `tone_thumb` — `batch_derive` + `develop_full(half: true)`, как левый
    кадр сравнения, без шумодава и резкости (на 276 px не видно, шумодав —
    самая долгая часть), отмена по `StopFlag` между этапами (`PairStop`)
    → `fit_thumb`. ~1 с на кадр. `thumb_one` (`refresh_thumb`, в т.ч.
    вставка настроек в неоткрытые кадры) — так же: с правками —
    `tone_thumb`, без — JPEG камеры с геометрией.
    **Обновление**: `Frame.geom` — геометрия, которую миниатюра
    показывает, `Frame.seq` — номер её расчёта (`st.thumb_seq`; результат
    старее показанного `take_thumb` отбрасывает). `sync_sidecar` →
    `sync_thumb`: геометрия открытого кадра сменилась (правка, откат по
    истории, вставка) — `refresh_thumb`: одна миниатюра в фоне
    (`thumb_one`, поток — в `thumb_threads`); вставка группы «crop» в
    неоткрытые кадры — `refresh_frame_thumb`. Для потоков из обработчиков
    в State есть `st.app`. **Только видимая часть ленты** (13.11.2026,
    аудит п. 4; раньше — вся папка сразу, ~200 КБ пикселей плюс текстура
    на кадр до выхода: 2000 кадров — ~400 МБ). `strip_thumbs`: видимые
    строки — по `strip.scroll_x`, `item_width` и ширине ленты; кадры
    дальше `strip_keep_screens` (4) экранов отдают миниатюру
    (`unload_thumb` → `clear_thumb`: заглушка 3×2 цвета фона — те же
    пропорции, ячейка выглядит пустой миниатюрой, — и `destroy_texture`;
    открытый кадр не отдаётся), в пределах `strip_load_screens` (2)
    недостающие заказываются `thumb_worker` списком `ThumbItem` (JPEG
    камеры, затем проявка кадров с правками) в порядке `thumb_order` от
    середины видимой части. `Frame.thumb` — что в холсте (0 нет, 1 JPEG
    камеры, 2 окончательная, −1 не читается — не просить); `st.thumb_req`
    — заказанное идущему воркеру (всё нужное уже заказано — не
    перезапускать; новый заказ останавливает прежний `thumb_win_stop`).
    Зовут: прокрутка вводом — `ListBox.on_scroll` (vgui, из обработки
    событий, не из рисования), `center_strip` (в `defer`: раскладка,
    сплиттеры, смена кадра, фильтр), `take_heads` (кадрам с правками —
    проявка), `load_folder`. Окно больше видимого вдвое с каждой стороны
    — увеличение окна программы до трёх раз не застаёт пустых ячеек.
    Пометки и правки кадров папки — отдельный `heads_worker`. Сборщик V
    памяти системе не отдаёт: RSS выходит на плато, но оно не растёт с
    размером папки (300 кадров: 591 → 515 МБ). Каждая миниатюра — через
    `post_result` в `take_thumb` (`thumb_gen` отбрасывает результаты
    старой папки; JPEG камеры после проявки того же расчёта — мимо).
    Смена папки/выход — `stop_thumbs` (`StopFlag`, атомарный `Flag` из
    workers.v: `set` / `is_set`), выход —
    ещё и `wait_thumbs`. ~25 мс на кадр; кэша на диске нет — не нужен.
    Миниатюра хранится только в пикселях холста (~200 КБ на кадр);
    `set_thumb_pixels` возвращает холсту размер миниатюры после заглушки,
    `draw_mark` по заглушке не рисует (отметку нарисует `take_thumb`).
  - **Множественный выбор** (`strip.multi_select`, vgui ListBox):
    Ctrl+щелчок, Shift+щелчок, Shift+←/→ — выделенные кадры подсвечены,
    в подписи над лентой «выделено N» (`strip_info_text`, по
    `on_select`); «Правка - Выделить все кадры» Ctrl+A —
    `select_all_frames` (`set_selection`, открытый кадр — последним,
    чтобы остался текущим и лента не прокрутилась; on_select
    set_selection не зовёт — подпись сам). Сочетание меню не отбирает
    Ctrl+A у поля ввода в фокусе (проверено: в поле угла выделяется
    текст). Нужен вставке настроек и экспорту; открытие кадра
    (`sync_strip` → `set_selected`) сбрасывает выбор в один кадр.
  - **Отметка «изменён»** — оранжевый кружок с тёмной обводкой в правом
    верхнем углу (`draw_mark`/`draw_dot`, со сглаживанием): при
    сканировании — `current > 0` в сайдкаре (`read_side_head`; с
    03.10.2026 одна пометка отбора или откат к «Открыт файл» правкой не
    считаются); после записи сайдкара не на «Открыт файл» —
    `mark_edited` из `sync_sidecar`. Только добавляется.
  - **Отбор** (`rating.v`, 03.10.2026): `Frame.mark` (`Mark`: звёзды
    0..5, флажок 1 / −1 / 0), у открытого кадра — ещё `st.mark` (из
    сайдкара в `open_file`). `set_mark` — на `mark_targets`: выделенные
    в ленте (`strip_selection`), без выделения — открытый; открытый —
    `st.mark` + `sync_sidecar` (создаёт сайдкар и без правок), прочие —
    `write_mark` (нет сайдкара — новый с «Открыт файл»; испорченный не
    трогается). Пометка не в истории и не в `EditState`; вставка
    настроек (`paste_to_file`) её сохраняет. Чтение при открытии папки
    (с 13.11.2026 — в фоне: `load_folder` читает только открываемый кадр,
    `thumb_worker` первым делом — сайдкары всех кадров и одной посылкой
    `HeadsResult` → `take_heads`: пометки, отметки «изменён», фильтр
    заново; на холодном диске тысячи открытий не морозят окно). Кадр,
    который тронули раньше (стал открытым — `sync_strip`, пометка —
    `set_mark`, правка — `mark_edited`, вставка, очистка истории), читается
    сразу `ensure_head`; `Frame.head` — уже прочитан, посылка его не
    трогает. Сама —
    `read_side_head`: первые 512 байт, `head_int` по ключам `rating`,
    `flag`, `current` (~20 мкс на файл; полный json2 — ~0.6 мс на 100 КБ,
    им — только старые сайдкары, где `current` после настроек). На
    миниатюре — `cv.on_overlay` холста ячейки (`draw_thumb_marks`, в
    экранных координатах, пиксели миниатюры не трогаются: смена пометки —
    `mark_dirty`): звёзды — залитые `RenderContext.fill_star` vgui (у Lucide
    звезда контурная; тёмная под светлой — обводка), флажок — значки Lucide `flag` / `ban`
    (`draw_icon_glyph`), отклонённый — затемнение; размер — от высоты
    миниатюры. В подписи над лентой — словами (`mark_text`), а рядом —
    звёзды `vgui.Rating` открытого кадра (`st.strip_rating`, значение ставит
    `strip_info_text`): щелчок — `set_rating` (как клавиши 0..5: выделенные или
    открытый), повторный по той же — снять; `focusable = false` — стрелки
    листают кадры, цифры — пункты меню «Отбор».
  - **Удалить отклонённые** («Отбор - Удалить отклонённые...»,
    Ctrl+Backspace как в Lightroom; 18.10.2026): все кадры папки с
    флажком −1 (`rejected_paths`, не только прошедшие фильтр) после
    подтверждения (`message_box`) — в корзину вместе с сайдкаром
    (`trash_frames`). Корзина — системная, файлы
    можно вернуть: Linux — спецификация freedesktop Trash 1.0
    (`trash_nix.c.v`: `$XDG_DATA_HOME/Trash/{files,info}`, `.trashinfo` с
    %-кодированным путём и датой, свободное имя `IMG.2.CR3`; файл на другом
    томе — `<том>/.Trash-<uid>`, `mount_top` по `stat.dev`; тест
    `trash_nix_test.v`), Windows — `SHFileOperationW` с `FOF_ALLOWUNDO`
    (`trash_windows.c.v`, `trash_win.h`, `-lshell32`; под Windows не
    проверено). Во время экспорта нельзя (воркер читает файлы); миниатюры
    и предзагрузка останавливаются, открытый кадр, если уходит,
    закрывается (`close_file` — на Windows открытый файл не удалить), потом
    `load_folder` и открытие ближайшего оставшегося (`after_trash`: после
    него, иначе до него).
  - **Фильтр ленты** (ComboBox `st.filter_cb` на полосе; `filter_keys`:
    all, picked, unrejected, rejected, r1..r5; не запоминается):
    `apply_filter` — `st.shown` (кадры фильтра) и пересборка строк
    ListBox из сохранённых ячеек `Frame.cell` (`clear` + `add_item_widget`).
    **Строки ленты ≠ номера кадров**: `row_of`, `frame_of_row`;
    `strip_selection` отдаёт номера кадров (им пользуются вставка
    настроек, экспорт, отбор); `sync_strip`, `center_strip`,
    `select_all_frames` — по строкам; двойной щелчок — `frame_of_row`;
    ←/→ — `next_shown` (открытый кадр может и не проходить фильтр),
    Home/End — первая/последняя строка. Пометка с фильтром — сразу
    `apply_filter` (кадр выпадает). Подпись: «2 из 5 (в папке 12)».
    Экспорт — вариант «По фильтру ленты» (`shown`), когда фильтр оставил
    не все кадры. «Переходить к следующему» (`settings.auto_advance`) —
    после пометки ОТКРЫТОГО кадра (единственная цель) `st.goto_frame`
    следующего кадра фильтра.
  - **Раскладка** — `layout_strip` пересобирает `st.viewer` (VBox.clear +
    add; **`VBox.remove` в vgui не работает** — сравнивает voidptr
    интерфейса и всегда false): без папки — только `view_stack`; лента
    открыта — вертикальный `Splitter` `st.vsplit` («просмотр | полоса +
    лента», мин. 200 | 106 px, старт ~170 px); скрыта — просмотр и одна
    полоса. Полоса (`strip_bar`): подпись папки/счётчика, фильтр и две
    кнопки-значка (`icon_button`): «Обновить ленту» (`refresh-cw`) и
    свернуть/развернуть (`strip_toggle`; значок
    `panel-bottom|top-close|open` и подсказку ставит `layout_strip` — по
    `strip_open` и `strip_top`). Ширина ячейки — `strip_item_width(высота
    панели ленты)`: миниатюра 3:2 во всю высоту над подписью;
    пересчитывается `fit_strip_items` по `vsplit.on_resize` (конец
    перетаскивания) и при сборке раскладки. При изменении окна высота
    ленты меняется пропорционально, ширина ячеек — нет (событий
    изменения окна в vgui нет): миниатюры просто вписываются.
  - **Обновить ленту** (кнопка на полосе, «Вид - Обновить ленту» F5,
    ключ `view.refresh`; 19.10.2026) — `refresh_folder`: `load_folder` той
    же папки (новые и пропавшие файлы, пометки из сайдкаров, миниатюры
    заново); открытый кадр остаётся (пропал с диска — без строки),
    выделение из нескольких кадров восстанавливается по путям, фильтр
    прежний. Следить за папкой сама программа не умеет — только по команде.
  - **Показать в папке** («Файл - Показать в папке» Ctrl+R, ключ
    `file.reveal`, доступен при `.target`; 30.10.2026) — файловый
    менеджер открывает папку кадра и выделяет его. Что показать —
    `reveal_paths`: кадр под курсором выделения ленты (`strip.selected`;
    без выделения — открытый, открытый не из ленты — его файл) и
    остальные выделенные из той же папки (менеджер открывает одну папку;
    с подпапками в ленте выделенные из других папок не идут; тест
    `reveal_test.v`). `reveal_in_folder(paths) !`:
    Linux (`reveal_nix.c.v`) — D-Bus `org.freedesktop.FileManager1.ShowItems`
    через `dbus-send` (Dolphin, Nautilus, Nemo, Caja, Thunar); ответ не
    ждём (холодный запуск менеджера — до секунды, окно не замирает), а
    есть ли служба, спрашиваем у шины заранее (`fm1_available`:
    `NameHasOwner`, `ListActivatableNames`, миллисекунды). URI — в
    %-кодировке (`trash_url`): запятая в имени не разобьёт массив
    `dbus-send`. Службы нет — `xdg-open` папки без выделения
    (`os.new_process`, не `os.exec`: тот читает вывод до EOF, а запущенный
    менеджер держит унаследованный канал — окно повисло бы). Процесс — в
    `State.reveal_procs`; закончившиеся забирает (`is_alive` — waitpid без
    ожидания) следующий «Показать в папке» (`reap_procs`), зомби не
    копятся. До 13.11.2026 его ждал фоновый поток, которого никто не
    соединял; ждать на выходе нельзя — xdg-open бывает жив, пока открыт
    менеджер. Windows (`reveal_windows.c.v`,
    `reveal_win.h`, `-lshell32 -lole32`) — `SHOpenFolderAndSelectItems`
    (PIDL папки + последние ID файлов, `CoInitializeEx` в потоке); кросс-сборка
    (`tools/windows.sh`) проходит, на самой Windows не запускалось. Ошибка — тост «Не удалось открыть папку».
  - **Переключение кадра** — фоновая загрузка (см. ниже): в главном
    потоке ~2 мс, сразу оверлей «Обработка» с кольцом прогресса,
    проявленный кадр — через ~0.75 с (24 Мп, -prod). Правки старого кадра не
    теряются: сайдкар пишется после каждой правки.
  - **Редактируемый кадр — по центру ленты** (`center_strip`): при
    открытии кадра (`sync_strip`), после изменения высоты ленты
    (`fit_strip_items` по `vsplit.on_resize`) и ширины просмотра
    (`hsplit.on_resize`). Ширина видимой части считается от доли

    видимая миниатюра заезжала на рамку (отсечение vgui расширено на
