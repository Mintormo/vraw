# Модуль imgio/ — запись кадра в файл

Часть документации vraw. Оглавление — [PROJECT.md](../PROJECT.md).

`imgio.write(path, fmt, w, h, rgb, quality:)` — 8-битный RGB-кадр в
файл. Без vgui (зовётся из save_worker). `Format`: jpeg, png, tiff, bmp,
qoi, gif; у формата — `name()` (для людей), `key()` (в настройках),
`ext()` (новый файл), `exts()` (распознавание и фильтр диалога:
jpg/jpeg, tif/tiff), `lossy()`; `format_by_path` — по расширению без
учёта регистра, `format_by_key`. Файл пишется атомарно (13.11.2026,
`write_atomic`): во временный `<путь>.vraw-tmp` рядом и переименованием —
сбой записи (кончилось место) в режиме «перезаписать» не губит прежний
файл, недописанный временный удаляется.

- **JPEG, PNG, BMP** — stbi из stdlib V (`stbi_write_*`). PNG у stbi
  сжимает слабовато и медленно (~4 с на 24 Мп, ~53 МБ), зато без
  зависимостей.
- **TIFF** (`tiff.v`, свой) — baseline RGB 8 бит, little-endian, полосы
  по 64 строки, Deflate (Compression 8) с горизонтальным предиктором
  (317 = 2), теги строго по возрастанию, данные по чётным смещениям,
  72 dpi, Software «vraw». Deflate — `C.stbi_zlib_compress` из уже
  слинкованного stbi.o (zlib-поток, как требует TIFF). **Грабля**: буфер
  stb выделяет через V (`stbi__callback_malloc` модуля stbi) —
  освобождать V-шным `free`, `C.free` роняет («free(): invalid pointer»).
- **16 бит на канал** (13.10.2026): `WriteOpts.bits16` — `rgb` из `u16`
  в машинном порядке (w·h·6 байт), только `Format.has_16bit()` (TIFF,
  PNG), другим — ошибка. TIFF — тот же `tiff_encode`, BitsPerSample 16,
  предиктор по 16-битным отсчётам (разность по модулю 2^16), в файле
  little-endian. PNG — свой кодер `png16.v` (stb пишет только 8 бит):
  IHDR 16 бит RGB, фильтр Sub у всех строк (шаг 6 байт), отсчёты
  big-endian, zlib — `zlib_compress` из tiff.v; EXIF и ICC вставляются как
  у 8-битного (`png_meta`, за IHDR). Сырые строки (~145 МБ на 24 Мп) —
  в bigbuf, освобождаются сразу после сжатия; `png_chunk` считает CRC
  по типу и данным подряд (`crc_ieee.update`), без копии IDAT. Тест `test_lossless16`: свой разбор
  обоих форматов — байт в байт; stb читает 16-битный PNG (сводит в 8 бит)
  в пределах 1. Вручную: `tiffinfo -D` и Pillow открывают без ошибок.
- **QOI** (`qoi.v`, свой) — байт в байт как эталонный qoi.h (RGB,
  альфа 255 в хэше).
- **GIF** (`gif.v`, свой) — один кадр, глобальная палитра 256:
  медианное сечение по гистограмме 5 бит на канал (делится коробка с
  наибольшим «число пикселей × протяжённость», по медиане вдоль самой
  длинной оси; цвет — среднее настоящих 8-битных цветов коробки), таблица
  «ячейка → ближайший цвет» на 32768, дизеринг Флойда-Стейнберга
  (ошибки двух строк в одном буфере — присваивать массивы в V нельзя),
  LZW как в gif.h: коды 9..12 бит, сброс при коде 4095, словарь — прямая
  таблица 4096×256 с «поколениями» вместо очистки, EOI — с размером
  кода, который декодер получит после последнего кода. Ограничение
  медианного сечения: цвета палитры — средние, до чистых 0/255 не
  достают, крайние тени и света чуть сдвигаются.
- **EXIF** (`exif.v`, 03.10.2026): `WriteOpts.exif` (`&Exif`, nil — без
  него; `Format.has_exif` — JPEG, PNG, TIFF). Блок — маленький TIFF
  little-endian: IFD0 (Make, Model, Orientation 1, Software, DateTime —
  дата записи, Artist, Copyright, ссылка 34665) и Exif IFD (ExposureTime —
  1/N для ровных долей секунды и всего короче 0.29 с, остальное десятыми:
  0.4 → 4/10, 0.6 → 6/10, 0.8 → 8/10, 2.5 → 25/10 (до 13.11.2026 0.4 с
  писалась как 1/3; тест `test_exposure_rational`), FNumber, ISO, ExifVersion 0232,
  DateTimeOriginal/Digitized, FocalLength, LensMake, LensModel); пустые
  поля не пишутся. Общий построитель IFD (`IfdEntry`, `put_ifd`: теги по
  возрастанию, данные длиннее 4 байт — сразу за IFD по чётным
  смещениям; `ifd_size` — чтобы заранее знать смещение Exif IFD) — им же
  теперь пишет и `encode_tiff`. JPEG: stb пишет файл в память (с APP0 JFIF), затем
  `jpeg_meta` вставляет APP1 «Exif\0\0» (`jpeg_exif_seg`) сразу за SOI и
  APP2 ICC (`jpeg_icc_seg`) за APP0/APP1; PNG (`png_meta`) — чанки iCCP
  (`png_icc_chunk`) и eXIf (`png_exif_chunk`) сразу за IHDR. Обе вставки —
  одной копией файла (с 13.11.2026; раньше `with_meta` копировал его
  трижды: clone, EXIF, ICC); TIFF — теги EXIF в IFD
  кадра, Exif IFD следом (`put_exif_ifds`). Тест `exif_test.v`: свой
  мини-читатель IFD (порядок тегов, чётные смещения, значения), JPEG —
  за сегментом тот же поток, PNG и TIFF читаются как прежде. Вручную —
  exiftool без предупреждений, значения экспорта IMG_0817 совпадают с CR3.
  Exif IFD несёт и ColorSpace (40961) = 1, sRGB.
- **ICC-профиль sRGB** (`icc.v`, 07.10.2026, шаг 1 «Управления цветом»):
  `WriteOpts.icc` (пусто — без профиля), экспорт (`write_image`, один и
  пакетный) кладёт `srgb_icc()` в JPEG, PNG и TIFF всегда — даже с
  выключенным EXIF (это описание цвета, не личные данные). Профиль свой,
  по спецификации ICC, без чужих файлов: v2.1, класс 'mntr', RGB → XYZ,
  ~2.5 КБ; wtpt — D50; rXYZ/gXYZ/bXYZ — матрица из цветностей sRGB
  (BT.709, белое D65) с адаптацией Брэдфорда к D50 (`srgb_d50_matrix`);
  rTRC/gTRC/bTRC — одна таблица `curv` (1024 точки) стандартной кривой
  sRGB, данные одни на три тега. Почему кривая sRGB, а не гамма 2.2
  пайплайна: тон подгоняется под камерный JPEG (тоже sRGB), превью на
  экране показывается без преобразования — с профилем sRGB файл в
  программах с управлением цветом выглядит как в окне vraw. Вставка: JPEG
  — APP2 «ICC_PROFILE\0» (часть 1 из 1) за APP0/APP1 в начале; PNG — чанк
  iCCP (имя «sRGB», zlib) сразу за IHDR; TIFF — тег 34675
  InterColorProfile. BMP, QOI и GIF профиля не держат. Проверка: lcms
  (Pillow ImageCms) читает профиль из всех трёх форматов, перевод в его
  эталонный sRGB на сетке 140 тыс. цветов — без единого отличия (оба
  намерения); exiftool — «Display Device Profile», ColorSpace sRGB.
  Тест `icc_test.v`: заголовок и теги, столбцы матрицы (известные D50-
  значения sRGB ±2e-4, сумма — белое D50), кривая (концы, монотонность,
  код 0.5 → 0.214), профиль на месте в каждом формате, без него — нет.
  Adobe RGB / ProPhoto не делаем (решение Игоря 07.10.2026: это для
  печати). Если вернуться: LibRaw отдаёт сырьё в sRGB и обрезает цвета вне
  его — без смены рабочего пространства выходной профиль выигрыша не даст.
- Прототип `stbi_zlib_compress` (TIFF) — свой заголовок
  `imgio/stbiw_zlib.h`: в stb_image_write.h он только в части
  реализации, а `fn C.` в V — только сигнатура (прототип V пишет лишь в
  модуле, линкующем библиотеку `#flag` без заголовков: раньше его давал
  флаг `-lm`). Без прототипа указатель обрезался до 32 бит (падение). Флаг `-Wl,--no-as-needed -lm`
  (обход старой ошибки линковки stbi) убран 06.10.2026 — не нужен с V
  0.5.2 1b4ecb9.
- Тест `imgio_test.v`: PNG/BMP/TIFF/QOI — байт в байт (PNG/BMP читаются
  stbi, TIFF и QOI — своими мини-декодерами в тесте, TIFF — полосы 1..4);
  GIF немногих цветов (разные 5-битные ячейки) — байт в байт (LZW со
  сбросами словаря); GIF градиента — средние по блокам 8×8 в пределах 3
  (вдали от краёв гаммы); JPEG — близко. Вручную проверено Pillow: все
  шесть форматов открываются, PNG/TIFF/BMP/QOI дают одинаковые пиксели.
