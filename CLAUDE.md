# vraw — проявщик RAW на V

Проявка RAW (CR3 с Canon R8/R50 и всё, что понимает LibRaw) в JPEG,
PNG, TIFF, BMP, QOI, GIF.
vraw — одно GUI-приложение на vgui (консольной версии нет): его
исходники (`module main`) — в корне проекта, бинарник `./vraw`.
Библиотечные модули в подпапках: `raw/` (обёртка LibRaw), `lens/`
(обёртка lensfun, коррекция объектива), `pipeline/` (собственный
тональный пайплайн), `ai/` (нейросетевой шумодав, ONNX Runtime),
`imgio/` (запись кадра в файл), `bigbuf/` (большие буферы вне сборщика
мусора).

Здесь — только постоянное: окружение, сборка, главный принцип
архитектуры, грабли. Пользовательское описание — в README.md.

**ОБЯЗАТЕЛЬНО прочитай `PROJECT.md` перед работой над проектом.** Там
подробное устройство модулей (raw/, lens/, pipeline/), формулы пайплайна,
устройство GUI и его паттерны, замеры скорости. План развития (что
сделано и что в планах) — в `ROADMAP.md`. Когда меняешь код, обновляй
`PROJECT.md` (и отмечай сделанное в `ROADMAP.md`); `CLAUDE.md` правь
только если изменилось что-то постоянное.

## Окружение и сборка

- Компилятор V: `~/soft/v/v` (НЕ в PATH сессии — всегда полный путь),
  с 06.10.2026 — V 0.5.2 1b4ecb9.
- LibRaw 0.21.2 из apt (`libraw-dev`), линкуется `#flag -lraw`.
- lensfun 0.3.4 из apt (`liblensfun-dev`), линкуется `#flag -llensfun`;
  свежая база профилей — в `~/.local/share/lensfun/updates/version_1`
  (подробности — в PROJECT.md, раздел про модуль lens/).
- vraw переносим: рядом с бинарником лежат `settings.json`, `models/`
  (модели AI-шумодава) и `onnxruntime/` (ONNX Runtime 1.30, грузится
  `dlopen`, не линкуется) — модели и ORT скачивает сама программа
  («Правка - Настройки»); всё это не в git. Без них тесты `ai/`
  пропускаются, программа работает без AI.
- Тяжёлые эксперименты на Python (квантование, калибровка ORT) — ТОЛЬКО
  под `systemd-run --user --scope -p MemoryMax=5G -p MemorySwapMax=0`:
  калибровка однажды съела 14 ГБ, OOM убил консоль.
- vgui: модуль ищется через симлинк `~/.vmodules/vgui -> ~/projects/vgui-python/v/vgui`.
  Библиотеки SDL3 — в `/usr/local/lib`. У vgui есть свой CLAUDE.md с контрактами —
  при работе над GUI сверяться с ним.

```bash
cd ~/projects/vraw
~/soft/v/v -prod -cc gcc -enable-globals .     # -> ./vraw
~/soft/v/v -cc gcc -enable-globals test .      # все тесты (рекурсивно, с модулями)
tools/portable.sh                              # портабельная папка dist/vraw/ (Linux)
```

- Сборка и тесты — ТОЛЬКО с `-cc gcc -enable-globals` (требование vgui).
- `-prod` (оптимизация gcc) — рабочая сборка: пайплайн в ~2.5 раза быстрее
  (превью ~19 мс с потоками вместо ~150). Цена — дольше компиляция (GUI ~30 с).
  Для быстрых итераций при отладке можно собирать без `-prod`.
- Сборка и тесты чистые — без notice и warning; новые не оставлять.
  Частые: `notice: variable X shadows a function declaration` (имя
  переменной совпало с функцией `module main`, в т.ч. с хелпером теста) и
  `mut p := buf` для указателя-параметра — писать `mut p := &u16(buf)`.
- `grep` без совпадений возвращает exit 1 — не путать с ошибкой сборки,
  проверять появление бинарника (`test -x vraw`).
- **Текст интерфейса — только через `i18n.tr('русская строка')`**
  (`trf`, `pl`, `trc` — PROJECT.md, модуль i18n/), перевод — во все
  `i18n/lang/*.json`; проверка `python3 tools/i18n_check.py`. Константы
  переводить там, где показываются (до `main` язык не выбран).
- Тестовый CR3: `IMG_0991.CR3` в корне проекта (тесты находят его
  через `@VMODROOT`; без файла — пропускаются).
- Визуальная проверка GUI: `DISPLAY=:0 ./vraw <файл> &`, скриншот
  `DISPLAY=:0 spectacle -b -n -o shot.png`, завершение `pkill -x vraw`
  (exit 144 — нормально, проверять `ps`).

## Архитектура

```
RAW-файл ──LibRaw (раз на файл)──> линейный 16-бит RGB ──pipeline──> 8-бит RGB(A)
           демозаика + камерный ББ    (сырьё в памяти)    вся тональная работа
```

Ключевое разделение: **LibRaw — только источник сырья, pipeline — вся
тональная работа.** GUI зовёт LibRaw один раз при открытии файла
(линейный 16-бит, half-size для превью) и один раз при сохранении
(полный размер). Тональные ползунки — повторный прогон `pipeline.apply()`
по уже готовому линейному буферу, LibRaw не участвует. Статичные свойства
кадра (коррекция объектива, шумодав) правят линейный буфер один раз
до пайплайна.

Превью и экспорт идут одним путём: `EditState` окна (с производными
полями — таблицы кривых, камерная кривая) → `pipeline.apply`; экспорт
(`export.v`, `develop_full`) берёт копию `st.edit` и повторяет подготовку
сырья превью на полном кадре. Пакетная обработка (в планах) — тоже в
окне, отдельной «проявки вне GUI» нет.

### Почему 16 бит достаточно

Сенсор Canon отдаёт 14 бит на канал; LibRaw после демозаики держит u16 —
запас 4x. 16 бит — только формат исходника: внутри `pipeline.apply()` вся
арифметика во f32, промежуточных округлений нет (как в darktable/Lightroom).
В 8 бит — только на самом выходе.

## Грабли и контракты (проверено на опыте)

- **vgui однопоточна**: все вызовы vgui только из потока App, с одним
  исключением — `app.post(fn ())`, официальный потокобезопасный мост:
  замыкание выполнится в главном потоке между событиями и рендером
  (см. CLAUDE.md vgui). Никаких других `spawn`, трогающих виджеты.
  Рабочий паттерн в этом проекте — `report()` в save_worker.
- **Тема vgui**: `create_app(theme: ...)` — тема приложения; окно без своей
  темы получает её в `add_window`. `create_window(theme: ...)` задаёт окну
  явную тему, её `App.set_theme` уже не меняет.
- **Длинное тире (—) нельзя** в заголовках окон и vgui.label — только дефис.
- Шрифт vgui знает не весь юникод: «↺» рисуется квадратиком (проверено),
  «×» (U+00D7) — работает. Экзотические глифы проверять скриншотом.
- Присваивание массивов в V запрещено (`array2 = array1` — ошибка):
  `.clone()` или переработать логику.
- Замыкания: капчур с mut — `fn [mut st, mut cv] (v f32) { ... }`;
  капчурить можно и значения (`name`, `i` в цикле создания EQ-ползунков).
- **Ошибки компилятора, исправленные в V 0.5.2 1b4ecb9** (проверено
  примерами 06.10.2026; в старом коде могут остаться их обходы — это не
  ошибка): анонимные структуры с указателями; замыкание в поле через
  элемент массива в цикле (vlang/v#28795); `[][]T{len: 4, init: f()}` в
  поле внутри json2; анонимная функция по умолчанию в `@[params]`;
  замыкания, державшие память (мусор в таблице замыканий); stbi после
  `-lm` при `--as-needed` (тихая пересборка запасным компилятором).
- **`fn C.foo(...)` — только сигнатура для V, C-объявление должно дать
  подключённый заголовок** (так задумано, см. doc/docs.md; свой прототип V
  пишет лишь в модуле, который линкует библиотеку `#flag` с `-l` или путём
  и не подключает заголовков). Без объявления gcc (V собирает с `-w`) молча
  считает, что функция возвращает int, и обрезает указатель до 32 бит —
  падение, а не ошибка сборки. Функции нет в заголовке (пример —
  `stbi_zlib_compress`, она только в части реализации stb_image_write.h) —
  свой заголовок: `#include "@VMODROOT/imgio/stbiw_zlib.h"`.
- `os.execute(строка)` устарел, в `-prod` это ОШИБКА сборки — запускать
  `os.exec(['tar', '-xzf', path, ...])` (без оболочки, ищет в PATH).
- `goto` — ключевое слово V (функцию так не назвать); в `_test.v` все
  функции с префиксом `test_` считаются тестами — хелперы называть иначе.
  Каждый `_test.v` компилируется отдельно: хелперы из одного тестового
  файла в другом не видны.
- Модуль `json` в этой V устарел (warning) — использовать `json2`:
  `json2.encode(v, prettify: true)`, `json2.decode[T](text)!`. Типа `!?T`
  в V нет. Поля структуры, в которые пишем (`f.history << ..`), —
  под `mut:`.
- vgui `ListBox` может хранить сложные виджеты (контейнеры) и быть
  горизонтальным (`list_box_h(item_width)` + `add_item_widget`) — на этом
  лента кадров. Строки-виджеты (`add_row_widgets`) в вертикальном
  списке рисуются только при наличии колонок, а `add_column` включает
  заголовок — после него `show_header = false`. Колесо прокручивает
  список под курсором без фокуса и на краю дальше не уходит (не брать
  колесо — `wheel = false`).
- **`VBox.remove`/`HBox.remove` в vgui не работают** (сравнивают voidptr
  интерфейса, всегда false): убирать виджет — пересборкой контейнера
  (`clear()` + `add`). `Splitter` вторую панель не сворачивает.
- vgui кнопки со значком: `icon_name` = имя Lucide (шрифт встроен),
  `style = .flat`; `Button.tooltip` НЕ рисуется — подсказка отдельным
  виджетом `vgui.tooltip(text).attach(b)`, добавленным в окно после
  корня (в vraw — `icon_button`, `st.tips`).
- vgui меню: `menu_bar()` + `add_menu`; сочетания клавиш — поле
  `shortcut` пункта, обрабатывает сам MenuBar (не дублировать
  `bind_hotkey`); флажок меню сам переключает `checked` перед
  `on_toggle`. Выбор папки — `native_select_folder_dialog`.
- Временную сборку запускать из черновика: настройки пишутся рядом с
  бинарником, настоящий `settings.json` она не тронет.
- Canvas: `stretch = false` (по умолчанию auto_fit) — вписывание с
  сохранением пропорций; `stretch = true` — растяжка на весь виджет.
- LibRaw: `unpack_thumb_ex` после `dcraw_process` — ошибка -4 (out of
  order); `raw.thumb_min` обходит вторым хендлом. Голый `unpack_thumb`
  отдаёт ПОСЛЕДНЕЕ выбранное превью (после `thumb_min(1000)` — 1620x1080,
  не полный JPEG): `raw.thumb()` выбирает самое большое явно.
- **`arr << s` и `for c in arr` КОПИРУЮТ массивы в `mut:`-полях
  структуры** (присваивание, литерал, spread — нет): буферы с владельцем
  (`bufown.v`) в такие структуры класть только по указателю (`[]&T`).
- Поток (`thread`) ждать `wait()` ровно один раз: повторный — аварийное
  завершение «V thread join failed: 3».
- База lensfun грузится ОДИН раз за запуск (`lens.load_db`, ~115 мс) и
  кэшируется в `st.lens_db`; профили — `db.find`. `lens.find` (своя
  база на каждый вызов) — только для тестов и разовых вызовов.
- vgui: отсечение (`push_clip`) расширено на 1 px наружу — содержимое у
  края может задеть рамку виджета; давать поле (ListBox `pad`).
- `@[params]`-структуры дают именованные вызовы `develop(half: true)`.
- Замыкания захватывают значения КОПИЕЙ, даже `mut`: int-счётчик или
  append в массив внутри замыкания снаружи не видны — счётчик/флаг держать
  в структуре по указателю (`&AiCtl`, `&StopFlag`).
- В повторяющихся местах (воркеры, прогресс, перетаскивание) замыкания
  не создавать (так было из-за ошибки V с памятью, сейчас исправленной;
  правило оставлено — так чище): результат из потока — `post_result`
  (post.v), прогресс — интерфейсом, приёмники — замыкания, созданные один
  раз при запуске.
- У `vgui.VBox`/`HBox` нет публичного `visible` (поле в приватном
  BoxLayout) — скрываемый контейнер класть в свой `vgui.Stack` (слой).
- Если V не смог собрать gcc, он МОЛЧА пересобирает запасным
  компилятором — тест проходит, но с мусором в выводе. При странном выводе
  смотреть `-showcc`.
- Приведение `&u16(buf.data)` (voidptr → указатель) — только в `unsafe`,
  иначе warning: писать `unsafe { &u16(buf.data) }`. Сборка и тесты сейчас
  без warning'ов (notice от vgui — не наши).
- Указательная арифметика только в `unsafe`; паттерн прохода по буферу:
  `mut s := &u8(buf.data)` ... `s += stride`.
- stbi из stdlib V: `stbi.stbi_write_jpg(path, w, h, channels, data, quality) !`.
- LibRaw: результат `dcraw_make_mem_image` живёт до `libraw_dcraw_clear_mem` —
  в V-обёртке это `DevImage.free()`, не забывать (иначе утечка ~36 МБ на кадр).
